# Memoria-Agent：小模型长期陪伴记忆研究与实验计划书

版本 v2 · 2026-10-11。以长期陪伴产品为主，配严格实验；本轮按用户新要求取消合成轨迹和合成公共基准路线，旧模拟数据、适配器及报告移除。当前模型为本地 BGE small zh v1.5 + Qwen3.5-2B，后期再比较约 1B 模型。本文全部里程碑和效果目标属于待实现/待验证；已有功能见 [implemented 导航](../README.md)。

## 1. 产品问题与研究问题

产品需要长期记住来源，认识用户当前习惯，理解真实变化、临时例外和共同经历，允许纠正与遗忘，并快速访问适用证据。外部记忆支持这些行为，不要求每次对话修改模型权重，也不等同于人的主观感受。

研究核心：在相同小模型、可见历史与上下文预算下，何时可复用一份有依赖版本的简短用户视图，何时必须重新检索或回查原话？能否降低访问成本，同时控制旧状态误用与过度个性化？“Claim + 增量视图 + 条件路由”是待检验设计，不能先称为原创算法或效果提升。

| 体验 | 可检验行为 | 主要指标 |
| --- | --- | --- |
| 记得久 | 跨会话回查既有来源 | evidence recall、可知问题 QA |
| 越来越熟悉 | 新历史使任务更符合当前用户 | 人工成对偏好、历史前缀曲线 |
| 不把人定死 | 临时需求不覆盖长期习惯 | 临时固化率、错误替代率 |
| 能够纠正 | 更正后旧版本不再用于当前回答 | 旧状态误用率、恢复耗时/轮数 |
| 有分寸 | 无关任务不过度套用个人信息 | 不适当个性化率、适用性 pair success |
| 访问快 | 常用状态少查历史，复杂问题回原文 | 访问 p50/p95、可见文本 TTFT、完整成本 |

## 2. 当前底座与缺口

已可复用：SQLite 事务、来源账本、人工审核、有效区间、版本替代/恢复、分块向量索引、FTS/BM25/Dense/RRF、情景层、提示预算、阶段计时和实验账本。

未完成：稳定 user/subject/predicate 键；证据 span 的支持度；真实世界事实时间与独立 recorded_as_of；事件参与者与条件状态；增量用户视图；视图依赖失效；全流程多用户身份隔离；实际 tokenizer 的整轮精确预算；后台游标回填与读路径 deadline。

特别边界：审核队列 completed 不表示候选已批准；当前共享空间 ACL 不覆盖旧个人聊天 runtime；有召回结果不表示证据充分；完整索引覆盖不表示整篇内容都进入 prompt。源码说明：[记忆一致性](../implemented/记忆一致性与检索审查.md)、[分块与记录](../implemented/实验记录与长记忆分块索引.md)。

## 3. 数据路线：仅真实来源

一期已准备 LCCC-base validation 的 50 段多轮微博对话、206 条原话，已归入 qin 的隔离实验空间（不是 qin 的真实个人发言身份），下载与来源映射见 [真实数据说明](../implemented/真实对话数据与实验入口.md)。仅用于中文表达、来源定位和抽取协议开发，不能拼接为一个用户的长期历史，不能补造身份、时间、偏好标签或 QA。

长期陪伴研究需要真正连续且获准使用的历史。下一步收集本人或自愿参与者的真实聊天导出，保持原始顺序、时间、角色与去标识化 ID；不同人物不能合并。先 3–5 人、每人至少 10 个实际会话验证流程；有真实数据再扩到 20 人，样本不足则缩小论断，不生成用户填数。

人工标注真实原话中的主体、属性、值、条件、事实时间精度、证据 span、陈述/推断/计划状态。没有证据的设定不可作为应知事实。两人独立核验，保存分歧与仲裁；单人阶段仅称开发诊断。Gold、未来对话和 probe 答案只供 scorer，不能进入检索或抽取。公开对话的许可按作者数据声明记录，私人数据单独保存且不进 Git。

禁止使用合成轨迹替代上述采集。LoCoMo/LongMemEval/Persona 类数据不能仅因公开发布就被叫作真实用户长期历史；本轮不保留旧合成基准入口或成绩，未来恢复任何基准前须先明确其生成方式并取得用户选择。

## 4. 可证伪的假设

| 假设 | 主要对照 | 判定证据 |
| --- | --- | --- |
| H1 结构化同槽位更新减少错误替代 | 当前整段相似候选策略 | 主体/条件正确率、旧状态误用、错误更新 |
| H2 依赖失效视图降低访问成本 | 同状态库始终检索/普通 TTL 缓存 | 同等质量约束下 p95、token、失效错误 |
| H3 预算内证据覆盖优于单纯 top-k | 固定候选的 RRF top-k | 多证据覆盖与 QA，固定 token 预算 |
| H4 收益在完整写入链路仍成立 | 只读已审核状态库 vs 生产增量链路 | 抽取/审核成本、worker lag、回答效果 |
| H5 约 1B 模型能承担可用自管理 | 固定 2B 与固定约 1B 分组 | 全程写入+回答质量和总成本，不能跨模型归因 |

质量容忍差值必须在开发集上预先登记，测试后不改阈值。若视图速度更快但旧状态误用显著增加，H2 失败；若人工状态库提升而端到端不提升，先解决抽取问题。

## 5. Claim 与变化判断设计

拟新增不可变 Claim revision：claim_id、memory_id、user_id、subject_id、predicate、value_json、polarity、modality、scope_json、fact_time_start/end、time_precision、observed_at、recorded_at/retired_at、status、source_message_id、span_start/end、source_hash、support_group_ids、verification_status、slot_revision、extraction_model_revision。

先实现居住地、职业/学校、表达语言、详细度、饮食、工作习惯、娱乐、学习目标、项目目标、时间、预算及重要事件等少数槽位。槽位元数据声明单值/多值和时间语义；喜欢 Python 与 Rust 可并存，旅行地不覆盖居住地。无法规范化的内容保留原文/事件，不硬塞 schema。

写入步骤：解析来源 → 提取带 span 候选 → 核对原文 hash/范围 → 检索同 subject/predicate/scope 候选 → 判定新增、强化、替代、条件例外、争议或跳过 → 人工审核 → 原子写 Claim、版本、来源与视图失效事件。陈述不代表现实已验证；同一来源或摘要回流不计多次支持。计划与已发生事件分别记录。

事实时间与系统获知时间采用独立半开区间；“最近”“上周”保留范围/粒度，不补成精确瞬间。迟到信息新增 revision，不能改写旧记录后宣称恢复历史所知。先支持限定槽位的 fact_as_of + recorded_as_of，再扩大自由文本。

## 6. 增量视图与访问路由

视图保留 user_id、scope、所依赖的 Claim ID/revision、来源、编译模型版本、index watermark、预算和有效期。更正、删除、来源失效、条件过期或主体映射变化触发相关视图失效；不能只按用户最近一次写入时间粗略判断。

路由四条路径：适用且有效视图直接读；缺项时补充检索；历史/共同事件回查原文；证据不足时澄清或拒答。先用确定性规则，再把歧义请求交给模型，记录路由原因。任一路径都携带来源并受相同预算约束。

证据选择在固定候选集上优化所需属性/时间/参与者覆盖，去除同来源重复块，保留互相矛盾但尚未解决的证据。片段可定位到父记忆；多块不成为多个事实。视图命中率须与有效性检查、错误命中和维护成本共同报告。

## 7. 工程与算法公平基线

| 组 | 配置 | 用途 |
| --- | --- | --- |
| B0 | 最近窗口，无长期记忆 | 下限 |
| B1 | 窗口内全历史，明确截断 | 长上下文参照 |
| B2 | 原话 BM25 / Dense / RRF 分组 | 读取基线 |
| B3 | 当前生产写入、审核与 RRF | 端到端基线 |
| B4 | 相同 planner/索引的工程优化 | 隔离后台回填、批量 hydration 提速 |
| B5 | 同 Claim 库始终检索 / 始终视图 | 路由必要性 |
| B6 | TTL 缓存 / 全用户失效 / 细粒度依赖失效 | 视图维护增益 |
| B7 | 同候选 top-k / 预算覆盖选择 | 选择器消融 |

固定 reader、embedding 权重、namespace、可见历史、上下文/输出 token、候选数、超时、温度、工具与审核策略；相同 top-k 和相同 token 两张表。工程提速不能归因于新算法。后期外部系统先锁作者版本，思想改写称 style 复现并列差异。

## 8. 两种真实数据评测

A：已人工核验的真实状态/来源库，只比较读取。它是有监督上限诊断，不代表模型已自主写入。

B：真实历史逐条到达 → 本地模型抽取 → 来源检查 → 固定审核策略 → 状态/视图更新 → 同一固定模型回答。主结论以 B 为准。2B 自写自答、约 1B 自写自答和 DeepSeek 教师写入条件分报；教师生成成本不能遗漏。当前不默认开启收费远程调用。

settled 条件等待任务及审核真正应用；live 条件按真实记录到达时间重放，不偷偷等队列清空。每次保留消息、抽取、批准、索引、视图 watermark。Probe 不写回未来历史。开发/测试按真实用户互斥拆分，重复表达和同一来源不能跨集合泄漏。

## 9. 指标与统计协议

- 写入：主体/槽位/条件准确率、span 支持度、错误强化、错误替代、临时固化、来源重复率。
- 读取：evidence recall、预算覆盖、QA、拒答适当性、旧状态误用、过度个性化、人工成对效用。
- 变化：从更正到实际回答恢复的耗时/轮数、失效传播与误复用次数。
- 性能：写入/检索/视图/reader p50/p95、可见文本 TTFT、后台成本、token/显存/CPU/磁盘、timeout/错误率。
- 数据量：真实用户、会话、消息、query 数和未知/不可判数，不能用多题冒充多用户。

失败和未尝试项保留在预注册分母；未调用角色成本为 null/0，缺 usage 标未知。按用户做 paired bootstrap，真实用户很少时只报逐人结果与不确定性。至少 3 次重复运行，冷启动/预热、并发 1/4 分报；嵌套墙钟阶段不能相加为总耗时。研究源文献数字不是项目 SLO。

## 10. 实验账本与产物

复用 `memoria/experiments/records.py`、`roles.py`、`observability/timing.py`。每次运行保存代码 SHA/dirty 指纹、数据 SHA/真实 ID、模型权重/tokenizer SHA、环境/硬件、角色参数、预算、启动结束时间、来源映射、原始调用/回答/错误、阶段耗时和产物 SHA。

下一步实现真实数据 runner 及独立人工评分入口；不能复用已删除的模拟 runner 的虚构答案。原始对话、prompt、token 和私人数据库只在 `data/`；提交经脱敏的来源清单、协议与指标汇总。模型版本未知就保留未知，不臆造 revision。

## 11. 12 周参考实施顺序

| 阶段 | 工作 | 交付/继续条件 |
| --- | --- | --- |
| W1–2 / P0 | 50 段真实公开对话抽取诊断；收集真实连续历史；人工核验 | 抽取空结果、归属错误与支持度清单；数据可追溯，无虚构标签 |
| W3–4 / P1 | user/subject/slot、span、Claim 事务；后台回填游标 | 同槽位更正正确，故障回滚，来源删除/撤销传播 |
| W5–6 / P2 | 条件视图、版本依赖失效、四路访问 | B5/B6 对照；更正后不使用失效视图 |
| W7–8 / P3 | 证据覆盖选择与精确 tokenizer 预算 | B7 消融，固定质量约束的预算/耗时表 |
| W9–10 / P4 | 完整写入链路、历史前缀曲线、真实用户留出 | settled/live 分报，失败分母与人工核验齐全 |
| W11–12 / P5 | 约 1B 全程对照；产品演示与研究结论 | 原始证据可回放，不支持的假设明确写失败 |

时间是安排，不是承诺数据已具备。每阶段完成再推进；若抽取仍不稳定则停在 P0，不通过自动批准、教师标签或模拟数据掩盖。实际数据未达规模时调整工期和结论范围。

## 12. 第一轮具体任务

1. 在独立 LCCC 库核对 50 对话/206 原话和来源映射，不把多说话者当成个人画像。
2. 人工选真实原话中确有长期价值的陈述，保留未知主体；按 production prompt 做 20 段抽取开发诊断，记录合法空列表与漏抽，先冻结协议。
3. 导入获准使用的真实个人历史到另一隔离库，保留稳定 user/时间/角色，建立只含真实来源的人工检查点。
4. 实现真实 runner 与 gold 隔离、失败分母、角色成本记录；冻结测试用户和 50 个可知 query 后才跑质量比较。
5. 用真实语料中的长来源验证 chunk coverage、纠正/撤销和 prompt excerpt；规模实验只扩大真实记录，不能复制文本充用户数。
6. 冻结 B0/B2/B3 与预算，再实施 Claim。每项更新 implemented 文档，普通提交 main，按 [提交规范](../implemented/github提交规范.md) 核验远程。

## 13. 后续界面与 MCP 边界

当前以 API、Swagger 和实验工具为入口。只有核心研究流程需要可视操作时，再做“来源证据 → 候选审核 → 状态变化 → 检索解释”的记忆控制台；聊天界面不作为当前主线。飞书/GitHub/网页 MCP 只提供外部只读资料入口，远程文档不能自动升级成用户事实，发布/发消息需另有用户授权。
