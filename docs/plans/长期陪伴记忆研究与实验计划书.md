## 1. 产品问题与研究问题

产品需要长期记住来源，认识用户当前习惯，理解真实变化、临时例外和共同经历，允许纠正与遗忘，并快速访问适用证据。外部记忆支持这些行为，不要求每次对话修改模型权重，也不等同于人的主观感受。

研究核心：在相同小模型、可见历史与上下文预算下，何时可复用一份有依赖版本的简短用户视图，何时必须重新检索或回查原话？能否降低访问成本，同时控制旧状态误用与过度个性化？“Claim + 增量视图 + 条件路由”是待检验设计，不能先称为原创算法或效果提升。

| 体验 | 可检验行为 | 主要指标 |
| --- | --- | --- |
| 记得久 | 跨会话回查既有来源 | evidence recall、可知问题 QA |
| 越来越熟悉 | 新历史使任务更符合当前用户 | 人工成对偏好、历史前缀曲线 |
| 不把人定死 | 临时需求不覆盖长期习惯 | 临时固化率、错误替代率 |
| 能够纠正 | 更正后旧版本不再用于当前回答 | 旧状态误用率、恢复耗时/轮数 |
| 有分寸 | 无关任务不过度套用个人信息 | 不适当个性化率、适用性 pair success |
| 访问快 | 常用状态少查历史，复杂问题回原文 | 访问 p50/p95、可见文本 TTFT、完整成本 |

## 3. 数据路线：仅真实来源

一期已准备 LCCC-base validation 的 50 段多轮微博对话、206 条原话，已归入 qin 的隔离实验空间（不是 qin 的真实个人发言身份），下载与来源映射见 [真实数据说明](../implemented/真实对话数据与实验入口.md)。仅用于中文表达、来源定位、抽取协议及开发 QA，不能拼接为一个用户的长期历史，不能补造身份、时间、无证据的偏好标签或答案。经用户授权可根据原话制作显式声明来源的开发标注；AI 填写不能冒充真人审核或正式教师监督效果。

长期陪伴研究需要真正连续且获准使用的历史。下一步收集本人或自愿参与者的真实聊天导出，保持原始顺序、时间、角色与去标识化 ID；不同人物不能合并。先 3–5 人、每人至少 10 个实际会话验证流程；有真实数据再扩到 20 人，样本不足则缩小论断，不生成用户填数。

未来人工核验路线：标注真实原话中的主体、属性、值、条件、事实时间精度、证据 span、陈述/推断/计划状态。没有证据的设定不可作为应知事实。恢复真人审核后，两人独立核验，保存分歧与仲裁；当前按用户要求暂跳过，不作为现有开发对照的阻塞条件，也不虚报已核验。Gold、未来对话和 probe 答案只供 scorer，不能进入检索或抽取。公开对话的许可按作者数据声明记录，私人数据单独保存且不进 Git。

禁止使用合成轨迹替代上述采集。LoCoMo/LongMemEval/Persona 类数据不能仅因公开发布就被叫作真实用户长期历史；本轮不保留旧合成基准入口或成绩，未来恢复任何基准前须先明确其生成方式并取得用户选择。

## 4. 可证伪的假设

| 假设 | 主要对照 | 判定证据 |
| --- | --- | --- |
| H1 结构化同槽位更新减少错误替代 | 当前整段相似候选策略 | 主体/条件正确率、旧状态误用、错误更新 |
| H2 依赖失效视图降低访问成本 | 同状态库始终检索/普通 TTL 缓存 | 同等质量约束下 p95、token、失效错误 |
| H3 预算内证据覆盖优于单纯 top-k | 固定候选的 RRF top-k | 多证据覆盖与 QA，固定 token 预算 |
| H4 收益在完整写入链路仍成立 | 只读已审核状态库 vs 生产增量链路 | 抽取/审核成本、worker lag、回答效果 |

质量容忍差值必须在开发集上预先登记，测试后不改阈值。若视图速度更快但旧状态误用显著增加，H2 失败；若人工状态库提升而端到端不提升，先解决抽取问题。

## 6. 增量视图与访问路由

本轮视图保存user_id、subject/条件/请求槽位、Claim修订/来源、确定性编译器版本、每槽位generation、字符预算与有效期；空槽位也登记依赖。generation不是Dense index watermark，未使用LLM编译摘要。后续设计再接入索引水位、语义编译与主体映射。更正、删除、来源失效、条件过期或主体映射变化触发相关视图失效；不能只按用户最近一次写入时间粗略判断。

路由四条路径：适用且有效视图直接读；缺项时补充检索；历史/共同事件回查原文；证据不足时澄清或拒答。先用确定性规则，再把歧义请求交给模型，记录路由原因。任一路径都携带来源并受相同预算约束。

证据选择在固定候选集上优化所需属性/时间/参与者覆盖，去除同来源重复块，保留互相矛盾但尚未解决的证据。片段可定位到父记忆；多块不成为多个事实。视图命中率须与有效性检查、错误命中和维护成本共同报告。

## 8. 两种真实数据评测

A：已人工核验的真实状态/来源库，只比较读取。它是有监督上限诊断，不代表模型已自主写入。

B：真实历史逐条到达 → 本地模型抽取 → 来源检查 → 固定审核策略 → 状态/视图更新 → 同一固定模型回答。主结论以 B 为准。2B 自写自答、约 1B 自写自答和 DeepSeek 教师写入条件分报；教师生成成本不能遗漏。当前不默认开启收费远程调用。

settled 条件等待任务及审核真正应用；live 条件按真实记录到达时间重放，不偷偷等队列清空。每次保留消息、抽取、批准、索引、视图 watermark。Probe 不写回未来历史。开发/测试按真实用户互斥拆分，重复表达和同一来源不能跨集合泄漏。

## 9. 指标与统计协议

- 写入：主体/槽位/条件准确率、span 支持度、错误强化、错误替代、临时固化、来源重复率。
- 读取：evidence recall、预算覆盖、QA、拒答适当性、旧状态误用、过度个性化、人工成对效用。
- 变化：从更正到实际回答恢复的耗时/轮数、失效传播与误复用次数。
- 性能：写入/检索/视图/reader p50/p95、可见文本 TTFT、后台成本、token/显存/CPU/磁盘、timeout/错误率。
- 数据量：真实用户、会话、消息、query 数和未知/不可判数，不能用多题冒充多用户。

失败和未尝试项保留在预注册分母；未调用角色成本为 null/0，缺 usage 标未知。按用户做 paired bootstrap，真实用户很少时只报逐人结果与不确定性。至少 3 次重复运行，冷启动/预热、并发 1/4 分报；嵌套墙钟阶段不能相加为总耗时。研究源文献数字不是项目 SLO。

存储路线分三步：

1. **本机/单机受控试用：** 保留每用户SQLite+本地磁盘，先补备份恢复、schema版本、配额、删除、投影一致性和维护。不要在多台机器间共享同一个网络盘WAL库；WAL的共享内存与单写者约束见[SQLite官方说明](https://www.sqlite.org/wal.html)。
2. **出现实测瓶颈或明确多机需求：** 以锁等待/尾延迟、磁盘增长、恢复窗口、跨机调度为触发条件，先抽象Store事务/来源/索引契约，再评估PostgreSQL、独立worker和对象存储。向量是否独立服务也由规模/质量/成本测量决定，没有“达到某条数就必须换库”的既定结论。
3. **跨机前：** 处理Windows用户绑定的DPAPI凭据与OAuth重新授权/机密服务迁移。复制加密blob不等于另一台机器可解密；数据库加密、备份加密、密钥托管和普通ACL分别验收，当前没有整库加密能力。
