## 目标与主线

2026-10-16主线调整：以 **Memory Formation → Consolidation → Evolution** 为研究核心，保留现有Evidence/Claim/Temporal/Governance/Hybrid Retrieval/RRF作为底座，不继续以增加检索通道作为主要贡献。[首版实现与边界](../implemented/记忆形成巩固与演化.md)已加入观察、跨会话模式、完整支持组、受约束演化及核心/归档投影；S0–S5仍是相关支撑和待验收项目，不能据此宣称完整自动学习已经实现。

下一阶段按以下顺序验证：先标记“明确自述/单次行为/不足以成模式”的真实来源，再标记跨会话必要证据与相反证据，最后验证形成/强化/变化/降级/撤销。观察覆盖、模式precision与误固化率、False Supersede、遗忘后泄漏/复活率、库膨胀和全链路调用成本优先于新的Recall@K。独立人工评估继续暂缓，缺少标签就报告未知，不以模型自评分或保存条数代替。

建议在相同来源前缀、Reader和总预算下比较：直接事实提取基线 / 加Observation但不巩固 / 加跨会话巩固 / 加受约束演化与核心投影。成本计入观察、整理、审核、索引和回答；未达到证据门槛的单次请求也计入分母。先做小规模真实检查，未经授权不重新全量运行LoCoMo；长期陪伴与抽取F1仍待真实连续资料验证。

回答项目的核心问题：**我怎样才能证明：这个系统真的在随着陪伴理解一个人，而且这种能力确实来自我设计的记忆机制？**

近期把“理解”限定为可核验行为：辨别人物和条件，维持当前/历史状态，回查共同经历，响应纠正与遗忘，并在有限上下文内使用足够证据。先把写入、变化、读取、撤回接成可重放的闭环，再研究训练式路由或更大的图系统。

建议集中形成一个主张：**通过有来源支持的条件状态维护与渐进证据访问，提高当前 Reader 在连续信息变化下的适用性与成本表现。** 这是研究假设；单独的 RRF、双时间、画像或缓存不作为独创贡献。

## S0：先把读写链路和评测分开记账

已有来源前缀重放、实验账本与 trace；本阶段补齐生产写入—审核—索引—View 的统一重放与归因。拟扩展 [experiments](../../memoria/experiments/README.md) 与 trace，不另建一套不可对照的生产记忆实现。每次请求至少保存：

- 可见消息截止与来源 SHA、实际角色/身份、query-only 解析结果；原始数据和 QA gold 分目录，仅 scorer 读 gold。
- 候选抽取 → 核验 → 提议关系 → 审核 → 事实版本 → 索引覆盖 → View 的事件 ID/水位与墙钟；不同状态不合并成“已记住”。
- 检索候选、每轮补检请求、邻句/时间线扩展、被过滤/未选原因、最终展示片段与引用；来源索引和已批准事实分别标识。
- 抽取、embedding、重排、路由、Reader、核验、重试、视图维护各自调用/usage；未知 usage 保留未知，硬预算同时留给回答和支持核验。

先冻结四类失败：未写入/未批准、未召回、候选未呈现、已呈现但回答或支持核验失败。缺条件/来源失效属于适用性问题，不能全部归因召回。使用固定代码与模型 SHA，模型未知 revision 如实记 null。

验收：在临时库重放事件后状态可核对，重跑不会重复强化，任意一次失败有稳定阶段分类；读取分数不得标作 Claim 抽取质量。测试用例只算工程验证，不导入真实账号或研究成绩。

## S1：支持组，而不是支持计数

Claim 已在 [claims.py](../../memoria/claims.py) 实现完整支持组和旧格式保守读取；普通记忆强化仍不等于保存了独立、可替代的充分依据。S1整体目标是在 [Store](../../memoria/store.py)、Claim及核验器上统一以下支持语义：

```text
Assertion support = Group A OR Group B OR ...
Group             = value evidence AND subject binding AND required condition/time evidence
```

1. 每组保存原始来源 ID、span/SHA、来源版本、适用主体/条件/时间和审核状态；组内允许多条原话共同支持。不同消息 ID 不自动等于不同独立来源。
2. 摘要、assistant 回声、重复导入或复制链共享 origin lineage，不增加独立支持数。用户再次确认可记录一次新确认事件，但次数不转换为真实性概率。
3. 某来源撤回时只失效依赖它的组；只有另一**完整且适用、已批准**的组仍存在才可继续使用事实。条件证据或跨句主体绑定缺失时，剩余值片段不单独放行。
4. “删除来源”和“删除这个事实/关于我的信息”具有不同范围；后者撤回整条 assertion 的可用性，不能因别组仍在就复活。旧记录的可见性继续遵守撤销优先规则。
5. 原话、普通记忆、Claim、组状态和 View generation 原子更新；不让异步索引或正在生成的回答把已撤回组重新发布。

Claim支持组直接落在现有模块，没有另建第二套权威存储。旧 evidence 保守作为一组读取，不自动拆成多个“独立支持”，不重写原审批或历史记录时间；普通记忆的支持表达与父记忆依赖仍待实现，不能从精确复制去重推导语义独立性。

对照：当前全部来源必需策略 / 不安全的任意片段有效策略（只作离线反例）/ 显式支持组。指标：剩余完整支持的保留率、必要条件缺失后的误保留率、撤回后泄漏/复活率、重复来源计数、有效历史与当前状态一致性。安全门槛为工程撤回反例全部通过；真实语义保留率待授权来源和可靠标签。

## S2：经历与事实分开，按需展开

为 [access](../../memoria/memory/access.py) 新增与批准 Claim 不同的原始经历入口；复用 Store 的权限、来源撤回、版本和模型 namespace，而非把公开语料或任意原话复制成个人 Claim。

拟保存可重建的来源索引：`source_id / session_id / speaker_id / observed_at / event_time(unknown allowed) / chunk span / source_version`。会话日期不等于事件发生日；公开来源的 speaker 不映射成本机账户 self。真实个人与公开 benchmark 使用不同实验命名空间。

```text
Query + 明确身份/条件/时间
  → 适用且完整的已批准状态可直接读 View
  → 经历/历史问题先查紧凑来源索引
  → 仅展开相关锚点的局部时间线/互补片段
  → 预算内批量取原文，复核依赖
  → Reader + 引用/支持核验，或明确缺项/拒答
```

已批准状态与原话的用途始终分开：“用户曾这样说”不等于“这就是当前已确认状态”。过去系统所知不能使用之后才出现的消息；recorded 语义在来源层先冻结截止点，再检索，不用事件日期代替。

具体先做：

- 保留多个高价值块的原文坐标，以父来源归组，再按必要事件/事实选择片段；不把多个块计为多个独立事实。
- 将 source ID 全量去重细化为原文区间重叠与重复信息控制。同一消息中不重叠且互补的片段可一起选，重复预算只计一次共享元数据；矛盾或条件组保持完整。
- 每次扩展限制锚点数、邻句范围、轮数、总输入/输出与 deadline；索引标题/摘要不能代替最终证据，也不让模型猜索引外 ID。
- 摘要索引先用可核对的抽取式标题，保留明确未知字段；若引入 LLM 摘要，记构建成本、源依赖和失效，不能用 QA 答案生成摘要。

对照：现有 RRF+邻句 / 有界多块 / 紧凑索引+局部展开；“全历史”保留成本参照，不作默认失败回退。固定候选池先隔离选择器贡献，再固定完整管线看召回与问答。需要报告索引/排序成本、必要证据覆盖、展示损失、最终 F1/引用和每题总 Token，不能只报告压缩率。

## S3：让更新决策明确表达状态变化

复用 [normalizer](../../memoria/memory/claim_normalizer.py)、[conditions](../../memoria/memory/condition_parser.py)、[relations](../../memoria/memory/claim_relations.py) 和 [update_policy](../../memoria/memory/update_policy.py)，先围绕现有12槽位迭代。人物实体只在当前账号命名空间内解析；跨消息别名/指代的解析必须有来源，歧义返回 unknown。

候选建议至少区分：同值强化、并存多值、不同条件例外、明确时间变化、计划/完成、冲突/待审。普通记忆相似 Top-3 可继续作召回种子，但更新目标应经主体/槽位/条件/时间约束重选；模型相关性分数不能批准覆盖。

临时 scope 增加明确生命周期绑定：session、用户明确的事件实例或明确有效区间。“这次”没有可确定绑定时留为待审/澄清，不能猜 TTL。生命周期终止后的旧例外不进入当前 View；事实历史仍按可用来源和时间权限查询。

后台可生成 Claim draft/关系建议与普通候选的对应关系，仍使用同一显式审核动作原子发布，不默认自动批准。将“只产生建议”和“确实应用变化”分开测；若以后讨论低风险自动提交，另行定义并验收准入策略。

指标：主体/槽位/值/span F1、Condition Accuracy、Update Decision Macro-F1、False Supersede、临时例外固化率、旧状态误答率、需要澄清却直接覆盖的比例。抽取必须同时记空结果、格式失败和未批准，不能只在成功候选上算 Precision。

现有 LCCC 缺真实人物/日期，LoCoMo 也没有完整的条件更新/支持 gold；缺标签的部分先做工程反例，不填真实抽取 F1。独立真人审核继续暂缓。

## S4：预算内选择与风险校准

已有全量结果显示自适应组普通 F1 51.15%，低于全历史 58.65%，Token/题也高于首次 RRF；因此暂不增加更多默认核验轮次，不用更多拒答来宣称更懂用户。旧四组使用不同预算，不能当作新同预算结论。

分两步试验：

1. **固定候选池：**RRF Top-K、现行词面 MMR、现行 Coverage、区间去重+互补片段选择；重排器另作独立开关。覆盖需求只由 Query、解析或预测产生，不能看正确证据 ID。
2. **固定完整预算：**直接读取 / 有界定向补检 / 来源渐进展开 / 校准后的充分性路由。所有组用同 Reader、可见历史、审批策略与调用上限，计路由、检查和失败成本；为 Reader+支持核验预留预算，剩余不足就停止扩展。

建议预登记 Reader evidence 2k/4k/8k token 三档；这些只是计划预算，须先核对实际 tokenizer/服务限额，无法精确测 token 的服务单列估计组，不冒充精确预算。每档都报告实际系统提示、工具、输出、核验及维护总账，不能只控制证据字符数。

门控状态分 sufficient / missing / conflict / unsupported / contract-error，缺失与冲突须有明确事实需求/相抵证据；contract-error 不算正确拒答。LLM 自信分、来源 ID 存在、字符串覆盖或合法 JSON 都不能单独当充分性 gold。

自动可测：普通 Token F1、回答率/拒答率、官方负例过答率、已知/未知 usage、执行失败和延迟；对抗短语分仅辅助报告。可靠语义标签可用后再测选择性风险、误拒答、真实支持度和校准误差，模型 judge 单列，不能充当真人结论。

拟用开发集登记非劣门槛：普通 F1 相对同预算基线最多下降1个百分点，官方负例过答率最多增加1个百分点，且全账成本至少降低20%；这些是**建议的准入阈值，不是已达到的数字**。使用按对话分组配对区间，小样本区间太宽则判证据不足，不能仅凭点估计通过。安全撤回/跨账号泄漏反例必须零回归，不用统计容忍替代硬约束。

## S5：有效视图的收益与维护代价

现有 View 为确定性编译，已有槽位 generation、TTL、未来边界和父记忆依赖；先测这些基础，再设计增量更新。不能把另一个模型生成的整段画像直接覆盖权威 Claim。

读取对照使用同一份已审核状态、相同输出内容和预算：始终 Claim 查询 / TTL 缓存 / 当前细粒度失效 View / 拟议增量 View。写入频率和查询热点从获准真实日志取得；没有日志时只报告不同工程负载的条件化测量，不能冒充真实用户使用比例。

分别测冷启动、命中、缺项、冲突、条件切换、迟到更正、来源撤回和索引滞后。报告 p50/p95、命中/错误命中、维护放大、索引覆盖延迟、每次正确回答总成本；空状态与有效状态分报。live 不等待后台和审核完成，settled 才等待，二者不能混合。

研究通过条件：不增加旧状态/临时条件误用，且加上维护后访问成本有可重复改善。若只有空库或长期效果资料不足，结果明确为未验证，不能从 SQL 次数下降推导人类陪伴效果。

## 数据、对照与因果归因

| 资料 | 本阶段用途 | 不能支持的结论 |
| --- | --- | --- |
| 现有 LoCoMo 10对话/1986题 | S2/S4 的公开长对话读取诊断；锁定原始 SHA、完整分母和官方证据异常 | 已经全量诊断并参与调参，是开发/探索证据；不能改名为未见测试集或本人真实长期效果 |
| LCCC50 | 中文表达、来源与未知身份保护 | 不串成同一人物，不能补造连续时间、画像变化和抽取 gold |
| 新获准真实连续资料 | S1/S3/S5 的来源演化、状态适用与 live 重放 | 当前尚缺，旧个人历史不自动导入；人工项暂缓时不声称语义标签已核验 |
| 工程临时输入/故障替身 | 迁移、撤回、竞态、预算和生命周期反例 | 不进入用户数据，不列入真实研究样本或质量表 |

后续外部基线优先复现一个固定 OSS Mem0 配置，再根据资源选择 Hindsight 或 Graphiti；claude-mem 用作渐进读取机制参照，编码工具观察不能直接当个人状态公平基线。原版与本项目重写的 style 方法分开命名。各组用相同历史/Reader/预算，并披露各方法原生更新与审批差异；不能仅把其他项目的宣传或论文分数搬到本表。

为证明收益来自本项目机制，至少保留这些消融：无长期记忆；只有来源 RRF；加入条件/时间更新；加入支持组；加入渐进展开；加入有效 View。先固定同一写入/状态库测读取，再固定同一 Reader 测端到端写入—审核—读取；按实际写入模型与回答模型的角色配置分报，任何人工审批优势单列。做“移除一个机制”的配对消融，避免把模型升级和工程加速归因给新算法。

获得真实连续资料后，按真实历史前缀绘制“熟悉度”行为曲线：每个截止点只使用当时已到达的消息，比较相同问题类型上的适用状态正确率、重复询问/错误个性化、纠正后恢复轮数与总成本。以截断记忆或移除某机制作为同一 Reader 的对照，probe 与未来原话均不写回历史。历史增长而表现没有改善、或者改善只来自更强 Reader，都不能支持“记忆机制让陪伴更有效”的结论。没有这类资料时不生成替代人物曲线。
