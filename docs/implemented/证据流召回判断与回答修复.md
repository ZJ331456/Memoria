# 证据流召回、判断与回答修复

2026-10-23。本轮依据原36题逐题审计修复候选裁剪、问题属性绑定、摘要扩写和支持核验之间的断点。继续使用生产MemoryKernel、原始来源、现有形成与审核机制；最终复测只登记完整Memoria一组。工程检查、模拟功能、实际BGE和真实题目效果分别记录，最终验收与完整结果见本文末尾。

## 适用路径与调用边界

[MemoryKernel.answer](../../memoria/memory/kernel.py)的自动路由保持原规则：`use_adaptive_retrieval=None`时，只有原问题规划为多个需求、且未同时启用独立查询模型或LLM重排，才自动进入缺项闭环。显式`True`可以使用该闭环；显式`False`保留原Reader路径。本轮没有把所有单事实查询改成默认自适应，也没有另造备用Reader。

下述类型绑定、完整支持判断及一次可选最小答案修复属于[adaptive_retrieval.py](../../memoria/memory/adaptive_retrieval.py)路径。资料域混合召回和原话摘要投影分别接入共享检索及资料Reader；不能据此宣称非自适应路径也执行了全部Gate和答案修复步骤。个人Claim/View、待修订状态、账号与会话边界继续由原Kernel检查，资料不能代替未获批准的个人状态。

完整流程为：原问题冻结需求→各通道召回与同额互补保留→有限Gate检查池→逐需求绑定与充分性聚合→必要来源闭合→Reader→独立支持及完整答题检查→必要时一次删减修复→再次独立支持及完整答题检查→发布前复核。缺项仍只有一轮、最多两条定向补检。共享调用/输入预算、来源版本与撤回核验贯穿全程；HTTP重试没有增加。

## 召回融合：同一名额内保留互补证据

[source_retrieval.py](../../memoria/memory/source_retrieval.py)继续按原权重和`weight/(60+rank)`计算RRF。[source_fusion.py](../../memoria/memory/source_fusion.py)在已通过来源有效性检查的排序上选择候选：

1. 至少保留一半名额的RRF头部，奇数向上取整。
2. 对各活跃通道的前四名轮转检查，优先保留原RRF前`limit`之外、尚未选中的候选；相同候选只占一个名额。
3. 剩余名额按原RRF顺序补齐，并把互补候选与保留头部交错呈现。

总`limit`不变。只有一个有效通道、或各通道没有提供原截断范围外的互补项时，保持原顺序。批准Observation与有效巩固仍可路由到原文；其通道排名没有成为事实或充分性证明。该选择器不读取题目答案、gold、原文语义或模型置信度，也不能保证前四名之外的关键来源被保留。

详细`candidate_selection`记录原融合名次、最终名次、选择理由及保护通道，保留至多64个裁剪ID并声明诊断是否截断；各通道有限排序、候选总数、实际保留数和邻接边分别记录。详细ID诊断留在捕获/自适应追踪；普通搜索先按完整原话及依赖选择，再在总JSON预算仍放得下时附加可选摘要，不足时省略响应里的`retrieval`，不因诊断挤掉原话或实体支持。捕获记录保持完整。后续Gate仍受有限条数和字符预算约束，其实际检查与遗漏ID另行记录；互补保留不意味着已送入Reader。

### 指代先行词的有限回看

原有邻接扩展仍只检查前四个入选候选，最多追加四段，总数不超过`min(16, limit+4)`。普通片段看前后各一条；以it/this/that/they/these/those或有限中文指代词开头时，依次尝试前一条、前两条和后一条，使中间隔一个追问的先行词有机会进入候选池。

每段保留独立作者、原始日期、版本、偏移和引用，邻接边记录`turn_offset`与`semantic_link_verified=false`。这只是检索线索，不能自动把“它”绑定到前文物品，或将同一邻域当作同一主体、事件及因果。两跳之外的关系和未识别指代仍可能遗漏。

## Gate：先绑定具体目标，再聚合充分性

[query_plan.py](../../memoria/memory/evidence/query_plan.py)只从原问题与解析范围冻结需求及`requirement_specs`，最多八项，超限保留“其余全部子句”需求。规格包含原问题跨度、请求目标、目标类型、精度、推断权限和计数范围，不预测应当回答什么值。

| 目标类型 | 必须建立的支持关系 |
| --- | --- |
| 属性、对象 | 引文识别实际被问的属性或物品，相关主题、赞美和未解决的指代不够 |
| 主体、事件及关系 | 保留请求主体、动作、对象、条件和同一事件关联，不用另一个人的经历代替 |
| 时间、区间 | 先支持目标事件，再支持事件时间或起止点；来源日历只能作有依据的锚点 |
| 集合、交集及计数 | 保留独立成员、原问题范围与去重依据；明确区分记录中提及数与指定事件总数 |
| 推断 | 只在问题明确允许推测时，允许从已有个人前提出发的有限、带不确定性的结论 |

Gate在同一次coverage调用中，为每个已支持需求提供`binding.value`、`basis`、`missing_components`及必要的`scope`。[evidence_sufficiency.py](../../memoria/memory/evidence_sufficiency.py)先验证原文引文与字段，再独立执行`assess_bindings`：检查目标值是否为空、是否仍有缺项、推断权限、同需求事件与日历绑定、请求主体、有限纯指代物品模式和计数范围。不完整绑定会降为missing，保留已有部分原话以便补齐缺环。

显式属性/物品绑定的具体值还须使用已引用原话中的词项。组织提示或机器描述提供名称时，必须同时引用对应的独立原文；不能只引用“我做了它”而从未引用的摘要补出物品。该检查不证明词项间的语义关联，最终答案仍可在独立核验后改写。

程序根据各需求状态聚合整体充分性，不能凭一句`sufficient`越过缺失或冲突，也不把模型的unsupported前提自动提升为可回答。这是两层逻辑检查，未增加第二个独立语义模型调用。程序仍不能证明引文真正蕴涵目标属性或同一事件；`semantic_sufficiency_verified=false`和`semantic_binding_verified=false`明确保留。

[select_closed](../../memoria/memory/evidence/closure.py)继续根据这些绑定闭合必要原话、身份、条件与时间支持组，记录绑定和引用节点。它不再被描述为能主动发现Gate漏掉的语义证据。必要组超预算不能删成员发布；已有逐字窗口压缩必须保留必要引文及限定，最终原话和依赖再次检查。

## Reader：隔离未闭合的Observation摘要

批准Observation描述继续参与召回，Gate可收到单独的检索组织提示；提示不属于可引用事实字段。原话上的组织摘要可能概括邻近但未被选中的来源，直接交给Reader容易产生“多写了一个正确细节，却没有相应原话引用”的问题。

[source_evidence.reader_packet](../../memoria/memory/source_evidence.py)对资料Reader作保守投影：原话候选保留Observation ID和`retrieval_receipt_only`回执，去掉组织摘要正文。原检索候选、依赖及撤回检查保持；没有删除已形成记忆或关闭形成召回。非自适应资料Reader也使用该投影。

明确的`consolidated_memory`候选仍携带完整呈现的原始支持组，不与单条原话上的组织提示混用。本轮没有自动把每条摘要依赖的所有邻近来源都塞进Reader，也不把摘要本身当作逐字原话。正文、实际呈现窗口、校验专用完整上下文和检索提示分别处理；校验专用上下文能发现被省略的限定，不能成为新增可引用字段。

## 回答支持：检查正确且答全，再允许一次删减修复

[AnswerRisk](../../memoria/memory/answer_risk.py)继续把完整答案拆成字面单元，要求所有实质内容均被核验，引文逐字来自指定原始字段。答案可以作受支持的同义表达，原话引文不能改写。支持模型另须为每个冻结需求返回`requirement_coverage`，并绑定真正回答该需求的受支持事实单元。

第一次支持核验和修复后的第二次支持核验都收到相同完整`query_plan`，都要求每项恰好出现一次并回答。只保留所有引用ID、却删掉问题的一半答案，不能通过；来源日期说明或相关背景也不能代替缺失事实。语义支持仍是独立模型建议，程序验证的是原话完整性、答案覆盖、绑定结构及明确边界。

第一次检查未接受时，[answer_repair.py](../../memoria/memory/answer_repair.py)只允许一次删减式修复：

1. 从原答案中保留已独立支持、通过本地约束且推断权限允许的完整单元。全局主体/高影响等阻断、整体矛盾或缺少安全单元时，不启动修复。
2. 在相同问题、相同呈现原话、相同必要引用和剩余共享预算内重新生成。只能按原顺序选择这些完整单元，允许分隔标点与空白，不能增加词句、截掉单元中的否定或条件、替换日期和主体。
3. 程序检查删减约束，再执行完整第二次支持及全需求检查，最后复核来源是否仍有效。仍失败则拒答；不继续补检、追加修复或放松支持标准。

答案删减与原有JSON契约修复是不同步骤。每次核验原有的至多一次契约修复，以及可选删减后的Reader和核验，都在同一单题调用/完整输入字节预算中预留并计费。预算不足会留下未尝试原因，不把未执行的修复当作成功，也不把未知usage记为零。

## 时间：允许有依据的推导，禁止从记录日期补造事件日期

Gate的`calendar_derivations`只对同一来源中明确的last/this/next year及对应中文表达，结合唯一来源年份给出程序算术提示。提示保留原文表达、同ID日历、年份精度及`event_identity_verified=false`；它不是新事件证据。Gate仍必须引用事件原话和完整同ID日期，核对是否为所问事件。月份、周和含糊recency没有扩成通用程序时间解析器。

[answer_dates.py](../../memoria/memory/answer_dates.py)在最终支持处复查日期精度与锚点：事件原话只说“已接受”“刚刚”或“最近”，不能配上来源日期就回答某个具体日；月、年或周也不能升级成原文未给的某日。拆开表达的日期单元必须依赖同一来源中受支持的事件单元，不能借另一个事件的时间。可确定的相对年份进行算术核对，其余推导仍受独立模型判断与原文精度约束。计划仍不等于完成。

周/月/年范围与定位它的参照日期分开：例如“3月16日前一周”仍为周精度，不能因句中出现3月16日就误判成事件发生在某日。询问提议/同意/决定的时间时，逐字的提议与明确同意本身是来源时刻的言语行为，可以用同来源日历定位；这不能证明未来合作已完成，也不能把回顾中的接受、旅行等事件强行归到记录当天。

`scope=source_metadata`仅用于狭窄的来源日期陈述模板，例如`The source date is <完整原始日期>`或`来源日期为<完整原始日期>`，只引用完整`session_date_raw`并标为explicit。该模板描述记录日历，不能夹带“所以事件发生在这天”的结论，也不能改写事件日期逃避事件锚检查。

本轮没有新增专门回答“这条来源的日期是什么”的元数据需求类型或路由。冻结需求的答全检查仍绑定事实单元，source_metadata不能充当事件问题的答案；直接询问来源日期的专门问法也未宣称全面覆盖，需要后续独立定义元数据目标及覆盖规则。单元契约允许某句来源日期说明，不等于整条Reader链已支持所有元数据问题。

## Caption输入与后验评测更正

[LoCoMo适配器](../../memoria/experiments/eval_benchmarks.py)默认`include_captions=False`，保留原`locomo-dialogue-text-v1`输入。显式开启后，已有`blip_caption`逐字文本作为独立`#blip-caption`来源导入，作者为`machine image caption (BLIP)`，标记`source_kind=machine_image_caption`。正文声明机器描述、父turn附件关联、非原说话人发言及未知事件时间；父说话人不是caption作者，也不因此建立本人事实。父会话只用于分组，caption的`session_date_raw`为空，不取得日期字段引用权限。

该过程没有读取图片、调用图像模型或OCR，也没有生成缺失描述。新`locomo-dialogue-and-blip-caption-v2`输入须在调用前与冻结登记一致；默认费用估算仍为零模型调用，正式执行仍要求显式execute、allow-remote及请求/美元上限。新旧输入的配对变化包含数据完整性差异，不能全归因于召回、Gate或长期记忆机制。

[eval_diagnostics.gold_locator_ids](../../memoria/experiments/eval_diagnostics.py)只在回答之后拆分一个官方定位单元格中以分号、逗号或空白组合的多个来源ID，保留未知格式并标记规范化版本。gold不进入查询、索引、融合、Gate、Reader或核验。该修复更正来源ID覆盖诊断，不改旧原文、gold、回答、Judge结果或历史分数；ID出现也不等于语义必要或充分。

[公开聚合导出](../../scripts/publish_fixed36.py)允许与旧Memoria单组完整检查点配对，执行/评分错误保留计划分母及unknown配对，不把技术失败当作正确拒答。公开仅导出白名单聚合及输入变化说明；题文、gold、逐题答案、原话、提示词、失败详情和SQLite留在账号私有实验目录。

定向测试覆盖互补候选、有限邻接、机器caption归属与无事件clock、类型绑定、摘要隔离、删减后答全、日期防补造、后验定位和公开隐私。这些是工程契约，不能代替真实效果评分、必要证据人工标签或长期收益。

最终工程、模型模拟、实际BGE和固定题结果按下列同指纹回执分别记录，不以功能通过替代语义质量或单模块因果收益。有限规则仍可能漏识别问法，单路前四名之外仍可能漏证据，Gate仍可能误判语义；歧义人名、计数口径和敏感身份不能靠放宽支持强行迎合标准答案。
