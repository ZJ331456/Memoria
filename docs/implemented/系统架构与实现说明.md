## 配置和运行

`main.py` 启动 Uvicorn；`memoria/config.py` 读取 TOML、extends 和环境变量，支持 main、fast、embedding。config目录按system/models/feishu/mcp管理，各自实际TOML忽略、example公开；模型与MCP的账号专属设置集中为UUID表。正式网关为每个账号指定独立DB、Markdown、MCP Host及加密凭据访问；旧数据库不自动导入。详见 [用户隔离](用户登录与数据隔离.md)。

依赖只安装到 `.venv`；MCP 的 npm 依赖与原生二进制安装在 `.mcp/node` 与 `.mcp/github`。模型权重在 `model/`。本地服务 `memoria/llm/server.py` 提供 `/v1/chat/completions`、SSE、工具调用和 `/v1/embeddings`；范围见 [统一接口](本地与远程OpenAI统一接口.md)。

## 个人记忆链路

消息落库 → 检索门控/规划 → 当前或历史有效区间及来源约束 → 共享词元索引/BM25/Dense → RRF、一跳图扩展与类型软配额 → 分层、来源片段和预算约束 → Reader/工具循环 → 发布前依赖复核 → 保存回复、trace与任务情景 → 租约worker抽取候选 → 明确审核后写入有效记忆。

普通记忆新增来源依赖/撤销账本、内容指纹和持久化词元TF/长度。候选在时间、来源过滤后排序截断；异步检索完成及输出前复核版本。引用普通记忆、历史或任务来源的答案缓冲后发布，可信内置工具在输出裁剪前传递依赖。索引缺项按全库当前模型空间统计，由后台小批量回填并持久化失败退避；读路径不做文档回填。批量读取元数据减少逐行SQL，实际线上SLO仍未测。完整证据见[逐项修复](内部记忆一致性修复记录.md)。

候选审核可明确核对完整Claim字段并联动批准；普通记忆、Claim和审核状态原子发布，冲突全部回滚。未勾选的普通审核不自动产生当前个人状态，复杂时序/否定继续走专用Claim修订。

候选先进入 memory_reviews；未批准记录不进入长期召回或 Markdown 投影。类型为 fact/preference/profile/goal/procedure。人工纠正新增版本，事务同时维护来源、替代、有效区间、FTS 和父/块向量；撤销可恢复此前来源仍有效的版本。来源账本防止同一来源重复强化。[一致性说明](记忆一致性与检索审查.md)涵盖迁移与恢复边界。

长文通过 BGE tokenizer 分块，原文连续 span 覆盖全文，每块最多 512 token（含 special token）。父记忆仅一份正文/版本，检索用最佳块给父记忆评分并提供 excerpt。[分块说明](实验记录与长记忆分块索引.md)区分完整索引与最终 prompt 可见内容。

## 分层、治理与来源

工作层限制上下文；情景层保存实际任务/对话片段；语义层保存审核事实；程序层与 Skills 复用经确认的方法；遗忘、纠正、过期贯穿生命周期。[分层配置](记忆分层与配置.md)说明 TTL、容量和预算，这些默认值不是研究效果保证。

共享治理使用 agents/spaces/grants/proposals/governed_memories/events 独立表与 `X-Agent-Key`。提案和审批重验权限及本地来源，CAS 防止并发覆盖。授权 SQL 候选内进行词面/BM25 检索；共享层尚无 Dense，个人运行时现已按登录用户隔离，共享空间仍是每用户库中的独立 Agent 治理域；跨登录账号共享尚未实现。[共享边界](记忆治理与多Agent共享记忆.md)。

来源接口可回查原消息、会话及上下文。来源存在不证明陈述真实；限定Claim已有哈希/span及有限语义规则，模型NLI仅提供建议，通用语义和现实核验仍待验证。

## 工具与可观测性

ToolRegistry 执行 schema 校验、授权、超时和输出裁剪；Tool Search 避免一次把全部工具放进模型上下文。MCP Host 管理 stdio 服务、白名单、并发初始化和 reload；本机接入方式与认证状态见 [MCP 部署](MCP部署与授权.md)。

轻量Pipeline/EventBus、会话压缩、SSE/取消、后台任务租约与受预算限制的空闲Drift已存在。Drift默认关闭，只做内部整理；飞书私聊长连接与独立账号绑定已接通，对外主动推送及动态插件市场尚未实现。

trace 记录召回来源/计划、模型 usage/重试、工具授权、阶段墙钟和可见文本 TTFT；`/metrics` 可供 Prometheus 抓取。实验账本记录代码、数据/模型 SHA、实际调用、失败和产物摘要。嵌套阶段有重叠，不能求和冒充总耗时或纯 GPU 时间。

## 本轮结构化状态链路

网关登录UUID → AgentService.claims → 独立Claim根/不可变修订/来源 → 明确批准 → 槽位/Typed条件匹配 → view/retrieve/history/clarify。`memoria/claims.py`负责事务、双时间、来源与缓存依赖；`memoria/api/claims.py`提供HTTP入口。新表与普通memories同账号数据库，Claim不镜像为Markdown/自由文本/向量，普通候选worker保持原有职责。

有限中文状态问题和只读access_claims接入运行时；指定状态问题跳过摘要/模型规划/普通召回，结构化上下文与工具结果完整保留或省略，trace保留claim.access阶段。限定实现、359项回归、真实副本迁移/服务验证及后续缺口见[Claim说明](Claim条件视图与访问路由.md)。

## Memory Studio和统一读链路

新studio是来源审核/双时间/检索解释/只读账本控制台，由正式网关同源静态托管。memoria/memory/access.py统一有限中文解析、Claim视图/时间线、普通来源补检与整组字符证据选择；个人问题运行时也使用同一编排。claim_analysis.py提供不写状态的建议，api/research_runs.py只读账号执行metadata/metrics，不开放脚本或gold。Claim不嵌入普通向量；来源补检不补为批准状态。详见[实现及验证](MemoryStudio与统一记忆访问.md)。

## 当前模型定位（2026-10-15）

本机后台实际使用 DeepSeek 大模型，Embedding 使用本地 BGE；OpenAI 兼容接口也支持其他远程配置及可选本地 Qwen。项目研究对象是记忆写入、适用状态与证据访问，参数规模不作为定位。此次同步修正中英文首页、海报及研究计划的旧表述，历史模型配置与冻结成绩不变。
