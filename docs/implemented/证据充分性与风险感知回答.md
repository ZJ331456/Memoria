# 证据充分性与风险感知回答

2026-10-13：针对普通题拒答与对抗过答的冲突，新增三个有限模块及独立LoCoMo消融入口。原全量结果、原始gold与个人记忆不改写；实现不把证据ID可见或F1=0直接解释为语义结论。

## 实现与边界

| 模块 | 行为 | 限制 |
| --- | --- | --- |
| [evidence_sufficiency.py](../../memoria/memory/evidence_sufficiency.py) | 分解最多4个必要事实；充分/缺项/冲突/无支持，缺项最多2条定向查询；逐条核对引用ID与原文连续片段 | 不是自信分数；模型语义建议仍需开发验证，原文命中不证明蕴含 |
| [answer_risk.py](../../memoria/memory/answer_risk.py) | Query-only时间、首次/绝对、条件、医疗、推断风险；独立提示核验每个回答单元和引用原话 | 同一Reader模型的额外调用，不是独立真人或另一模型；非推断问法不接受仅背景推测的个人事实 |
| [adaptive_fallback.py](../../memoria/memory/adaptive_fallback.py) | 缺失事实/相关时间线补检；每题最多6次模型调用、累计完整输入160000 UTF-8字节，最多2轮补检 | 不读完整历史给Reader；远程精确Token窗口仍未知，Token只从实际usage统计 |

支持判断必须提供事实/回答单元与原文引用，不接受confidence、gold或任意额外字段。引用逐条验证实际展示ID、连续原文；生产多原文span不能拼成伪造的连续证据。冲突要求两个不同来源；缺失事实不能携带虚假支持。所有候选、预算、查询、升级理由、模型输出及契约失败保留在账号私有执行账本。

统一访问仍保留已批准Claim、条件整组、双时间和账号隔离。新模块不自动批准或把自由文本晋升为本人事实。

## 生产Reader的显式开关

登录`/api/memory-answer`的QueryRequest新增`use_answer_risk`，默认false。开启后先做带引用的充分性检查，充分才调用Reader；回答通过原引用契约后再做支持检查，最后重验来源/Claim版本。非充分或支持未通过时拒答/澄清，返回结果不包含被拒绝的回答或模型原始判断文本。

```json
{"query":"我默认用什么语言回答？","scope_mode":"default","use_answer_risk":true}
```

此开关可能额外调用模型，最多3次；默认行为保持。生产当前仅接入前后检查，**生产定向补检尚未接入**，避免重写Query时放宽原主体、条件或时间约束。完整分级回退先由独立benchmark入口验证；`/api/memory-query`仍是检索诊断，不因该开关自动调用Reader。支持检查通过仍标记`semantic_entailment_verified=false`，不冒充独立语义保证。

## 先分类检查旧案例

[locomo_diagnostics.py](../../memoria/experiments/locomo_diagnostics.py)只在推理之后读取gold，核验完整私有产物SHA与祖先账本，生成本地检查队列：166道普通拒答、100道已回答但F1=0。规则分类是后续审查线索，不是自动语义裁决。

166道拒答：44道时间/前提检查、46道Reader/主体/条件检查、64道语义跨度/表述检查、2道证据未定义、10道背景推断/高影响检查。164道标注ID全可见；120道参考答案未在整段原文中找到完整字面出现，不能据此认定不可推断。

100道零F1：31道候选/呈现缺口、2道原标注异常、4道背景/高影响、48道语义/措辞、15道时间/前提检查。27道回答在其引用原话中有字面出现，仍可能答非所问或对应另一事实；不直接算语义正确。规则类别互斥，风险/字面标志可重叠，独立语义审核未完成。

旧账本补齐已知Token/题：首次RRF **3986.38**，完整历史复核 **18414.96**，均包含记录的工程重试；已知Token分别7916959与36572111，未知usage/3在途费用不计为零。详细问题、参考答案与原话只留账号reports，公开只提供汇总与指纹。

## 新消融预登记与命令

[注册协议](../../configs/research-locomo-risk-20261013.json)固定开发集为原顺序前两段对话的全部304题，正式全量仍为1986题。原全量已经用于诊断，不能把新拆分宣称成从未看过的测试集；不按gold/F1挑选在线查询或改变标签。

- `targeted`：原RRF首次回答；拒答/非法输出才做缺项规划和一轮定向补检，再读紧凑证据，不使用充分性决策门控或回答支持检查。
- `adaptive_risk`：Reader前判断必要事实；缺项/时间关系补检，充分才读；回答后支持未建立可再补检，预算耗尽拒答。证据阶段12000/16000/20000字符，与完整请求/累计字节约束分别计量。

两个新方法使用同一Reader、英文BGE、原始题目及评分。缺项查询仅访问同一冻结对话的RRF索引，每轮最多2条查询，合并排名后最多80候选；相邻原话仍受实际证据JSON预算约束。没有全文Reader、外部搜索或gold字段。格式失败单独记录，实际费用包含规划/核验，不能只报最后一次Reader Token。

```powershell
# 仓库根目录，已有私有profile；实际远程调用计费
.\.venv\Scripts\python.exe scripts/research.py --user qin locomo-run --scope development --fallback targeted --input data/benchmarks/locomo/raw/locomo10.json --embedding-device cuda --profile deepseek --roles configs/research-remote-roles.toml --allow-remote --concurrency 4
.\.venv\Scripts\python.exe scripts/research.py --user qin locomo-run --scope development --fallback adaptive_risk --input data/benchmarks/locomo/raw/locomo10.json --embedding-device cuda --profile deepseek --roles configs/research-remote-roles.toml --allow-remote --concurrency 4
# 同参数改 --scope full 为全量；每次新建run，不覆盖旧实验
```

开发验证对“官方不可答题”及“原文直接出现参考答案且对应证据已展示”的有限正样本检查充分性门控；这只是带明确范围的代理标签，不代表所有时间推断/多跳题的真实充分性gold。指标与最终QA及对抗拒答共同报告，不用模型自评或ID召回来宣称已经具备真正可答性判别能力。

工程全量543 passed / 162.46s（新增实现基线）；补充模型元数据、风险规则及CLI后受影响76 passed / 21.08s。真实实验结果随后追加。新方法尚未证明F1/拒答/成本的综合收益，因此不替换生产默认；长期本人效果、独立语义审核与商业验收继续按[研究计划](../plans/长期陪伴记忆研究与实验计划书.md)推进。

全局回归后补充首次阶段诊断归属及生产故障成本返回，最新受影响51 passed / 23.26s；67份Markdown/622个本地链接锚点、既有首页24个评分值与冻结聚合SHA检查通过，根README保持用户要求的精简状态。实际执行需记录本次干净提交与模型快照；此阶段未新增实验分数。
