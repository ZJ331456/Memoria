网页Chat、HTTP聊天API、飞书、QQ与Telegram共用AgentRuntime，正常完成一轮后均按用户消息ID创建唯一memory_job，没有只对网页启用的分支。后台异步抽取最多3候选，再由LLM主审决定低风险入库或人工辅助；浏览器刷新只读状态，不触发提取。一次性资讯/执行请求可以返回0候选，此时没有审核对象，不能等同自动审核关闭；解析/网络错误会重试或失败，不冒充成功空结果。

## 为什么出现这次错误

`value_not_literal; semantic_or_alias_review_required`来自普通记忆与Claim联合批准的规则校验，并非Embedding索引故障。原来只要结构化值不符合有限词面/别名规则，就整批回滚，没有继续调用LLM确认忠实改写。普通记忆正文和结构化短值是不同字段；将整段正文填到某个属性值中也可能触发该错误。

现在人工联动遇到纯改写/别名问题时，先调用LLM作Supported/Contradicted/Insufficient语义判断；只有Supported且来源、主体、条件、否定、事件时间及冲突约束仍通过才允许提交。主体/条件/时间错误不会被一个Supported覆盖。模型未就绪或不支持时用中文解释，并允许取消Claim联动、仅确认普通记忆；不会为了消除提示而关闭所有校验。

## 当前生产流程

1. 原生日常聊天结束后，持久任务提取最多3条候选。提取覆盖明确事实、偏好、目标与持续项目约束，保留项目/条件范围；临时问题、助手建议、他人事实和凭据不保存。
2. 默认`[memory.worker] approval_mode="llm"`。另一次模型调用检查候选长期价值、原话支持、主体、条件/时间和唯一原样引用；不给出一个置信分数就直接批准。完整来源超预算不截断，留人工辅助。
3. 服务器另行执行身份/公开归属/撤销/SHA/span检查。明显凭据直接拒绝，识别到的敏感事实先转辅助。2026-10-20起，有限场景条件经原文分句与条件证据核验后可自动发布；未知前提（如果/除非等）、周末/时段、历史/未来时间、状态变化、计划/假设、混合主体或未绑定否定仍转辅助。
4. 低风险Supported普通记忆在同一事务发布记忆、审核结果及审计。精确去重可强化；自动路径不自由覆盖旧记忆。12类结构化事实可创建并批准无条件或有限条件Claim，事实时间仍未知；无合适槽位也能只写普通记忆。Observation提供当前候选的原文定位，不能从同一原话的另一条观察偷换事实。
5. 相同值/极性/场景、未知事实时间的已批准当前Claim，在独立LLM接受新自述后，自动追加并批准reinforce修订，新完整支持组绑定本次普通记忆及正文SHA；组内AND、组间OR，原文副本不增加独立来源。审核记录实际新修订ID，不仅复用根ID。不同值的单值冲突、已知事件时间的强化仍保留受约束修订审核；多值槽位可共存。自由语义合并与自动状态转换仍待验证。
6. 网络或解析失败、引用不唯一、约束变化不会强制写入。失败决定按候选/来源/策略指纹保存，后台只选择尚无评估的候选，避免辅助积压阻塞新项；已有决定不反复收费，用户可明确重新调用。

`approval_mode="manual"`可保留全人工流程。该配置是服务端管理员配置；Studio显示当前策略，普通用户不能用前端字段改别人的策略。

## 历史怎么转入长期记忆

Studio → 历史对话 → 本人用户原话旁“LLM提取并处理” → 确认只处理这条原话。后台提取及审核后，在“候选审核”的全部记录查看LLM已入库/需人工辅助/已拒绝；成功项可进入长期记忆库。不要把一段临时提问当成用户长期事实。

已有候选不重复抽取；旧任务完成但没有候选时可以由这个明确操作重新处理，`memory_job_reprocessing`保留旧任务回执。不会读取全部旧个人历史或自动重提取全部公开资料。手动提出候选仍可用，提交后按当前策略处理。

候选中的“LLM审核并尝试入库”可审核修改后的文本；自动审核、网络失败与人工确认均有清楚区分。人工按钮及结构化字段收进辅助区域，合法改写允许LLM语义核验。

## 审计、预算与限制

`memory_review_assessments`追加记录策略、输入指纹、决定、原因码、实际模型及已知usage；缺失usage保留未知，不记录模型置信分数当真值，不对外发布原话或提示词。模型、Embedding都在事务外调用，提交前重新核验来源和候选；批准及审计原子发布。取消/失败不留下半个Claim或有效记忆。

单条抽取最多3候选，各一次审核；后台每轮至多补处理1个未评估候选。`model_called=false`表示这次规则阶段未调用审核模型，不代表原聊天或索引维护从未调用模型。提取与审核通常使用fast（就绪时）或main，不增加新的默认云供应商。

实际DeepSeek小检查使用本会话已有真实用户指令，系统临时库保存，未写生产：长期项目目标候选获Supported并入库，临时问句被拒绝；初版提取提示对项目目标返回0，补齐持续项目范围后一次提取返回1。共4次真实请求、0重试；两次审核已知token为457/446，更新后的提取225，首次提取usage未捕获，不能相加当完整总成本。该检查只证明链路可用，不是抽取F1、错误自动批准率或长期收益。
