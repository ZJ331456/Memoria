# 已实现：真实历史、人工标注与独立评测 runner

核对：2026-10-12。入口是项目 `.venv` 中的本地管理员 CLI，不是匿名 HTTP 接口，也不提供聊天前端。研究产物按现有账号 UUID 隔离；这些工具不会往生产 memories、审核队列或后台任务写入候选。当前采用真实公开对话做开发诊断；真正的连续个人经历仍需要有来源、有同意范围的聊天导出。

## 本机 50 段真实来源

```powershell
.\.venv\Scripts\python.exe scripts/research.py --user qin use-public
.\.venv\Scripts\python.exe scripts/research.py --user qin annotation-template --dataset lccc-base-validation-multiturn-50 --reviewer qin_review_v1
```

本机已执行这两步：复用 qin 已导入的 LCCC-base 50 段/206 原话，逐条核对数据库映射、原文和 SHA，再写独立研究来源。重复接入核对后复用；任何原文、来源声明或 SHA 变化均拒绝覆盖。

固定的 conversation/source ID 只标识来源分组，不能称为真实人物 ID；原始 message ID 和 content SHA 可长期定位原话。所有 speaker、事件时间保持未知；manifest 的 imported_at 是真实导入时间。不同对话不会被拼成一个人的经历，qin 是数据空间所有者。整个公开集合限定 development，不能据此报告用户留出或长期变化效果。

## 目录与隐私

```text
data/users/<UUID>/
  research/registry.db                   来源/人物划分/不可变审核/冻结协议的摘要
  research/sources/<dataset>/            history.jsonl + manifest.json
  research/drafts/                       人工标注及评分草稿，含原话，不提交 Git
  research/protocols/<protocol>/         inputs.jsonl / gold.jsonl / 独立审核与仲裁
  experiments/<run_id>/                  manifest / prompts / calls / cases / events / metrics
  experiments/<run_id>/scores/           单独评分版本，不改预测账本
  secrets/deepseek.research-model.dpapi   当前 Windows 账号加密的私密模型配置
```

CLI 的 `--user` 由账号库选择服务器生成的 UUID，不接受自选数据根路径；所有研究子路径检查越界、符号链接和 junction 解析。CLI 拒绝把另一账号的私密文件当输入，也排除旧 personal archive。它是操作系统管理员入口，不能代替 HTTP 登录；同一 Windows 用户仍能直接访问私密文件。详见 [用户隔离](用户登录与数据隔离.md)。源文件不可覆盖，摘要同时登记 SQLite；修改历史、授权声明、冻结输入、gold 或预测后会拒绝继续评测。文件系统与 SQLite 不是跨介质事务；极端发布中断可能留下未注册目录，工具拒绝静默复用，应核查后用新 dataset/protocol ID 重做。

## 真正连续个人历史的导入协议

```powershell
.\.venv\Scripts\python.exe scripts/research.py --user qin import-history --input <获准使用的本地JSON路径>
```

输入须是 schema_version=1 的 JSON 对象，下列字段来自真实导出和参与者同意，不由工具补造。可以含多个实际会话，但同一 conversation 不能混入不同参与者。

| 字段 | 必需内容 |
| --- | --- |
| kind / dataset_id / provenance | `consented_personal_history`、稳定标识、真实导出来源说明 |
| participants | 每人稳定去标识化 id、split=`development` 或 `test`、consent |
| consent | granted=true、purposes 包含且仅包含 memory_processing/annotation/evaluation、带时区 recorded_at、同意依据 reference |
| messages | 实际原始顺序；id、conversation_id、participant_id、speaker_id、role、content、observed_at |
| role / speaker_id | user 或 assistant；user 的 speaker_id 必须等于 participant_id；禁止把助手陈述当本人发言 |
| observed_at | 实际消息时间且含时区；不是工具编造的事件发生时间 |

逐人物检查时间不倒序、消息 ID 不重复、参与者均获准、同一人物不跨开发/测试划分。人物 ID 的真实性与别名对应关系依赖提供者核实，工具不能独立验证人的身份；修改别名规避划分也不是有效研究。解析通过不表示来源真实性已独立验证。当前不导入旧个人历史。

## 人工标注与双人审核

annotation-template 生成账号私有草稿，附上实际 source_context，facts/probes 为空，status=draft，annotation_seconds=null；不预填事实、问题、答案或完成状态。第二名审核者单独从原文建草稿，不自动看到前一人的标签。

阅读原文后填写：

- `status=completed`、实际人工耗时 `annotation_seconds`；仅标事实时可设 `scope=extraction_only`，不必虚构 QA。
- facts 每项：id、participant_id、subject_id（未知=null）、predicate、value、conditions、fact_time（未知=null）、statement、modality=statement/inference/plan/unknown、evidence。
- evidence 每项：message_id、start/end（Python Unicode 字符索引，半开区间）、quote、content_sha256。须与原文切片及 SHA 完全一致。
- probes 每项：id、participant_id、cutoff_message_id、question、answerable、人工 accepted_answers、evidence。不可知题也要人工给出可接受的拒答表述；可知题必须有证据，证据不能来自截止点以后或其他人。

公开对话的事实主体和 fact_time 必须为 null，participant_id 此时只是已有的来源分组 ID。标注提交后不可覆盖，更正须用新审核版本 ID；不同版本不能冒充不同审核者。

```powershell
.\.venv\Scripts\python.exe scripts/research.py --user qin submit-annotation --input <填好的私密草稿路径>
.\.venv\Scripts\python.exe scripts/research.py --user qin freeze --dataset <真实dataset_id> --protocol <新的protocol_id> --reviewers <审核者ID>
```

两人审核时 `--reviewers` 传两个独立实际审核者。事实/probe 不一致会拒绝冻结；须提供第三位审核者填写的完整有效标注文件，包含 resolution，使用 `--adjudication <私密文件>`，保留两份原标注、分歧与仲裁。工具检查不同 ID，不保证不同 ID 必然属于不同人。单人只允许开发诊断；含 test 的协议至少两人审核。extraction_only 标注不能冻结成 QA gold。

## 抽取、QA 与来源隔离

```powershell
# 生产一轮抽取提示词；不自动批准候选
.\.venv\Scripts\python.exe scripts/research.py --user qin run --mode extract --dataset lccc-base-validation-multiturn-50 --limit 50

# 主体未知的公开来源诊断，显式记录与生产提示词的区别
.\.venv\Scripts\python.exe scripts/research.py --user qin run --mode extract --dataset lccc-base-validation-multiturn-50 --limit 50 --extraction-protocol source_grounded --roles configs/research-local-roles.toml

# 完成人工协议以后；每次执行全部冻结 probe，--limit 不裁掉 QA 分母
.\.venv\Scripts\python.exe scripts/research.py --user qin run --mode qa --protocol <protocol_id> --baseline B0_recent
.\.venv\Scripts\python.exe scripts/research.py --user qin run --mode qa --protocol <protocol_id> --baseline B2_fts
```

production_turn 复用生产抽取提示词，最多三项；公开原话附有未知归属说明。source_grounded 是独立的开发诊断协议，最多两项；模型提供引用，程序只在原文唯一匹配时计算真实 message ID/span/SHA，歧义或改写拒绝。精确引用不等于候选语义确实受支持，仍须人工判断。两个协议及修订分别记录，不能把提示词改善归因于模型大小。

QA 冻结时将原文前缀/问题写 inputs，人工答案/证据写 gold。run 仅读 inputs，不加载 gold 或人工 facts 到模型；评分单独运行才读 gold。B0 是最近 N 条；B2 是截止点之前的临时 SQLite FTS5 trigram/BM25 原话检索，三字片段 OR 查询，没有隐式换用最近窗口。它不是生产 Dense/RRF 或完整 B3 写入链路。窗口与检索都受同一序列化字符预算，超预算会记录遗漏；不是精确 tokenizer 预算。Reader 需返回 JSON answer/evidence_ids，引用未呈现来源记异常。真实连续历史重放的 live/settled 写入策略、Claim、视图、Dense 基线仍待实现。

## 单独人工评分与失败分母

```powershell
.\.venv\Scripts\python.exe scripts/research.py --user qin score-template --run <run_id>
.\.venv\Scripts\python.exe scripts/research.py --user qin score --run <run_id> --judgments <填好的评分草稿路径>
```

抽取草稿包含实际原话与未核验模型候选；人工填写 reviewed、supported/useful/attribution_correct=true/false/null，正向支持和人工发现的 missed_facts 需准确原文 span。没有填写的项目保留未知；漏抽项仅报人工发现数量，不伪装为完整 recall。空抽取需要人工阅读后判断是否漏抽，不能直接当零质量或满分。

QA 可先不传 judgments 单独计算字面答案匹配；NFKC/大小写/空白归一后的 exact rate 不是语义正确率。人工正确性填 true/false/null，保存 reviewer、实际耗时、预测 SHA。证据统计目前是 message 级 recall，不是语义支持度或 span recall。失败项保留在全部预注册分母；已知人工项、未知项、下界及状态分开报告。评分不会反向改变预测或模型输入。

每次运行独立 run_id，记录代码/输入/模型/tokenizer SHA、角色参数、真实 prompt/response/error/usage、非流式 TTFT=null、阶段墙钟及 p50/p95；未调用角色与未知 usage 不补造成本。正常完成、合法空结果、错误、取消、未尝试分别保存。进程硬退出无法自动执行 finally，可在确认进程停止后恢复：

```powershell
.\.venv\Scripts\python.exe scripts/research.py --user qin recover-run --run <run_id> --confirm-stopped
```

仍在运行的已记录 PID 会拒绝恢复；未记录完成的在途任务标 interrupted_unknown，其余 not_attempted，执行结束和 elapsed_ms 保留未知，不从恢复时间补造。重跑生成新目录，不重复写生产库。

## DeepSeek 对照与私密激活

```powershell
.\.venv\Scripts\python.exe scripts/configure_research_model.py --user qin
.\.venv\Scripts\python.exe scripts/research.py --user qin run --mode extract --dataset lccc-base-validation-multiturn-50 --limit 50 --extraction-protocol source_grounded --profile deepseek --roles configs/research-remote-roles.toml --allow-remote
.\.venv\Scripts\python.exe scripts/research.py --user qin activate-model --profile deepseek --validated-run <有真实候选的run_id>
```

Key 隐藏输入并用 Windows DPAPI 保存，源码与配置文本仅存 profile 名，不保存明文 Key。激活只修改 qin 的 main/fast，保留本地 BGE；校验实际 run 模型、端点、账号和非空证据候选，不把“非空”当成人工批准。业务服务重启后加载，其他账号不继承 qin Key。编辑端点使其与 profile 不符会拒绝加载。

2026-10-12 核对官方文档并实际请求 /models，本账号有 deepseek-flash、deepseek-v4-pro；不能沿用旧别名假装固定模型版本。当前接口默认开启思考，可能用完小输出额度，项目增加官方 API 限定的显式 thinking=disabled；其他供应商和 local:// 不接收该字段。依据：[官方模型入口](https://api-docs.deepseek.com/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。DeepSeek 收到明确发送的公开原话；默认不调用远程，必须显式 --allow-remote。

本机真实运行记录与阶段状态见 [研究计划](../plans/长期陪伴记忆研究与实验计划书.md#当前进度与下一步)。人工 gold 尚未完成时不报告语义 QA、变化适应或陪伴质量成绩。
