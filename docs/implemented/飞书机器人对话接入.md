# 飞书机器人：私聊接入与账号绑定

2026-10-14。此模块接收手机/桌面飞书里发给应用机器人的私聊文字，使用当前绑定账号的Memoria Agent回答。飞书MCP仅是Agent调用文档/云盘工具，MCP OAuth成功并不会自动接收机器人消息；两条链路独立。

## 已实现链路

```text
飞书 im.message.receive_v1
 → 官方SDK长连接子进程
 → 校验应用/人类发送者/私聊，持久化去重收件箱后ACK
 → 一次性绑定码映射到服务器账号UUID
 → 该用户独立运行时，共用HTTP会话锁/取消/Reader/记忆/trace
 → 持久化答案 → 飞书原消息回复
```

只支持人类用户的p2p文字；群聊、机器人自身消息和其他应用事件不进入Agent。附件/语音/图片输入暂不解析。未绑定者只收到绑定说明，不调用模型、不自动创建账号，更不会把所有人归入某个预设用户。账号绑定后，飞书对话是该账号的原生聊天，在Chat和Studio可查看，公开实验语料的归属与Claim资格保持。

## 平台配置

在[飞书开放平台](https://open.feishu.cn/app)进入你自己的应用：

1. **应用能力 → 机器人**：确认已添加并启用机器人，应用可用范围包含你的飞书账号。
2. **权限管理**：申请“获取用户发给机器人的单聊消息”`im:message.p2p_msg:readonly`，以及“以应用的身份发消息”`im:message:send_as_bot`。
3. **事件与回调 → 事件配置**：订阅方式选择“使用长连接接收事件”，添加“接收消息”`im.message.receive_v1`。
4. 创建并发布新版本，确认需要管理员审核的权限已经生效。

本机只需能访问飞书HTTPS/WSS，不使用公网回调、内网穿透或OAuth回调URL。旧MCP的localhost:3000/callback是OAuth授权回跳，不是手机消息接收入口。平台若提示先建连接，先完成下节的本地配置并启动后台，再回来保存事件配置。

依据：[官方服务端SDK入口](https://open.feishu.cn/document/server-docs/server-side-sdk)、[Python SDK](https://github.com/larksuite/oapi-sdk-python)、[接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)、[回复消息](https://open.feishu.cn/document/server-docs/im-v1/message/reply)。本机固定Python SDK 1.7.4，不把第三方教程或目录收录当作验证。

## 本地安装与私密配置

从仓库根PowerShell执行，只使用项目.venv：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-feishu.txt
# 有现有飞书MCP加密应用凭据时复用；只复制应用凭据，不复用用户OAuth授权
.\.venv\Scripts\python.exe scripts/configure_feishu_bot.py --from-user your_username
# 没有现有文件则在终端输入，Secret隐藏
.\.venv\Scripts\python.exe scripts/configure_feishu_bot.py
.\build_frontend.cmd
.\stop_backend.bat
.\start_backend.cmd
```

两种配置命令选择其一。也支持`--credentials-file 私密JSON路径`；文件只应存在Git忽略的本地位置，不向聊天或issue粘贴。`--config`用于其他私密项目配置。禁用接收：

```powershell
.\.venv\Scripts\python.exe scripts/configure_feishu_bot.py --disable
# 随后停止并重新启动后台
```

应用ID/Secret保存在`data/config/feishu-bot.credentials.dpapi`，Windows当前用户DPAPI加密；`data/config/feishu-bot.json`只含enabled。机器人入口默认关闭，其他机器clone不会获得你的应用、绑定、会话或凭据。MCP账号凭据/授权文件保持独立。

## 手机与Memoria账号绑定

1. 在本机浏览器打开Chat根地址，登录要使用的Memoria账号；Studio也有相同入口。
2. 点击右上角 **连接飞书**，确认“机器人长连接在线”，再点击 **生成绑定码**。
3. 在手机飞书私聊你的机器人，发送页面显示的完整`/绑定 …`命令。不要公开绑定码。
4. 收到“绑定成功”后直接发文字。新会话标题以“飞书”开头；原话、助手回复、来源和运行trace保存到该账号。

绑定码十分钟有效、一次性、重发即作废；服务端只保存码摘要。绑定命令中的码在入箱前即转换为摘要，不作为本人原话或记忆。每个应用内一个飞书身份对应一个Memoria账号，每个Memoria账号也只对应一个飞书身份；已有其他绑定时必须先解绑。绑定尝试每发送者十分钟最多5次，模型对话最多30次；全局最多4个渠道任务，同一发送者串行。

正常文字通过权限与绑定检查后先回复“已收到，正在处理”，再加载账号工具和调用模型；避免把MCP初始化或模型等待误认为没有收消息。该提示不包含用户原文，使用独立稳定UUID。入箱同时记录绑定的账号和绑定版本，排队期间换绑也不会把旧消息移入新账号。

| 私聊命令 | 行为 |
| --- | --- |
| `/help` 或 `/帮助` | 显示绑定与使用说明 |
| `/绑定 绑定码` 或 `/bind CODE` | 连接自己的账号，不生成对话事实 |
| `/new` 或 `/新对话` | 下一条文字开始新的飞书会话 |
| `/stop` 或 `/停止` | 优先停止当前生成并清空该发送者待处理消息 |
| `/unbind` 或 `/解绑` | 解除绑定；已有聊天保留在原账号 |

网页解绑会取消该账号在途渠道任务。账号被本机管理员停用后也不能继续访问模型或数据；网页单次退出不等于取消外部渠道授权，离开公共设备请关闭网页会话，需要撤销飞书访问则明确解绑。

## 隐私、失败与运行边界

- 状态接口不返回应用ID、Secret、tenant token、飞书用户标识或其他用户状态；绑定接口只取正式登录身份，不接受客户端选择owner。
- SDK运行在后台所属子进程中，屏蔽可能包含原始消息/凭据WS URL的SDK日志；不把凭据放命令行。内部收件箱在Git忽略的`data/channels/feishu.db`，是普通本地SQLite，包含短期未处理消息，**不等于整库加密**。实际聊天库的磁盘保护仍按用户隔离/商用计划实施。
- message_id持久化去重，ACK不等待LLM。回复使用稳定UUID，网络失败最多3次重发已保存答案，不重复生成；进行中的生成若进程重启则记中断，不自动再次计费。不能承诺跨网络/平台的数学意义exactly-once。
- 已完成收件箱清除正文与答案，七天后的终态元数据在启动恢复时清理；未完成/重发记录保留，聊天正本在用户库。输入过旧或早于绑定不进入Agent。
- 长回复按UTF-8保守分段，上限截断时提示完整内容在本地查看。解绑或账号失效后重新核对归属，不再发送私密答案。
- 一个本地监听租约防止重复业务实例抢收件箱；官方SDK负责连接断开重连。子进程若异常退出会显示状态错误，需要查看无凭据状态并重启后台。多worker、多机器与完整商用监控尚未验收。

## 接口与诊断

| 接口 | 登录及行为 |
| --- | --- |
| `GET /api/channels/feishu` | 本账号是否绑定、长连接就绪/错误码；不返回凭据 |
| `POST /api/channels/feishu/pairing` | 生成本账号一次性绑定码，禁止公开返回内容 |
| `DELETE /api/channels/feishu/binding` | 解绑当前账号，不删除已有聊天 |

没反应时先看连接弹窗：未配置→运行配置命令；sdk_missing→在.venv安装可选依赖；listener_already_running→只保留一份业务后台；在线但无事件→检查平台事件/发布/可用人员和是否私聊应用机器人；收到绑定指引→完成账号绑定；收到模型错误→在Studio检查真实运行记录；数字发送错误码→按飞书平台排查权限/可用范围/消息状态。不要把完整SDK日志、Secret或绑定码提交到issue。

真实验收：官方凭据认证、机器人能力查询、WSS端点获取均成功，长连接实际在线；用户确认平台配置发布，并明确反馈“绑定并收到正常回复”。只读核对本地账本，绑定码已消耗、个人绑定存在，绑定确认和普通Agent回答的发送记录成功，飞书会话写入对应账号。已有一条turn_cancelled中断记录原样保留；慢速停止确认会取消自身的竞态已用隔离测试复现后修复，不重跑真实消息、不修改历史状态或重新计费。私密逐条记录、账号标识、正文和usage不公开。

最终相关118 passed / 62.36s（24项渠道工程及94项既有回归）。前端10项与双入口类型/构建通过；SDK有两项弃用提示，未造成执行失败。启用机器人后本机后台真实停止/重启及再次在线通过，.venv依赖检查通过。手机普通文字收发接通不证明回答语义、长期记忆效果、完整多平台SLO，也不产生新的benchmark成绩。
