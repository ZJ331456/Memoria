## 0. 第二轮（2026-10-23）：子集复用、修复追加与命中上限

登记：[locomo-deepseek-cache-20261023.json](https://github.com/ZJ331456/Memoria/blob/38648d3/eval/protocols/locomo-deepseek-cache-20261023.json)，布局`deepseek-reader-input-prefix-v2`。

1. **引用子集改为复用Reader前缀**：旧策略对只引用子集的支持核验退回独立短请求，等于整段证据冷付。DeepSeek命中价是未命中的1/50，复用长前缀通常比发短冷请求更便宜；新策略用`task_evidence_ids`把可引用证据限定回原子集，引用校验不放宽。`subset="legacy"`保留旧行为用于A/B。
2. **修复轮并入共享前缀**：修复指令从消息0移到任务System位（证据之后），修复请求成为已持久化单元的扩展，不再是冷请求。契约校验、调用上限与预算不变。
3. **报告同时给出结构上限**：`deepseek_cache.ceiling`按"每case首次请求仍为冷token"计算可达上限，避免用重复填充抬高命中率。

冻结账本复算（0模型调用，按调用顺序）：定向组首次请求7,820,198token中已命中7,437,839，后续1,346次调用只命中8.6%；自适应组首次请求8,270,279token中命中3,202,089，后续4,140次命中36.2%。按新布局把后续请求的冷token转成复用，投影命中率定向组约90%、自适应组约66%（后续调用90%转命中时约93%/74%）。该投影是账本结构推算，不是实测；实测仍需新登记下的开发题。

已发现但未改：自适应组首次请求（充分性门）只命中38.7%，而同题Reader达78.3%，两者证据集不同；把证据数组改为按来源顺序的确定性排序，可能再提升15–20个百分点，但属于呈现顺序变更，需单独A/B与质量检验。

**2026-10-23审核更正**：证据条目重复率不能推出provider前缀命中率，不能据此断言各阶段偏移是唯一瓶颈，亦不承诺90–95%。候选v3登记保留原字节作为提议，生产布局及子集/修复默认以[最新审查](DeepSeek缓存优化详解.md#代码处置)为准。下方两题与完整模拟是旧核心历史记录，不是当前改造的质量收益。

## 2. 官方机制与生产改造

DeepSeek默认复用已经持久化的相同输入前缀，以完整单元保存；建立需要时间，命中是尽力服务，闲置缓存可能回收。相同字符、相邻调用和长输入均不保证命中。输出补全的`prefix`不是KV缓存开关。[官方缓存说明](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)

只有精确HTTPS主机`api.deepseek.com`（默认端口/443）启用。其他供应商、代理域名和本地OpenAI格式服务保留原提示词。不加预热、填充、TTL或缓存key；不跨账号共享项目状态。确定性JSON只排序对象键，保留证据数组顺序、原文与全部版本/时间/来源字段。

生产Kernel/资料Reader的充分性与支持核验采用`deepseek-evidence-prefix-v2`：固定安全System → 原证据包 → 独立任务System → 问题/答案等变量。普通Reader原布局保留。两个核验仍独立调用，先前模型判断与助手答案不能作为新来源证据。来源撤回、引用子集、完整支持组和发布前依赖复核仍生效。

原子预算模式要求整个必需前缀与请求装得下；不足明确阻断，不能删证据换命中。Reader、支持核验和一次修复仍预留完整预算。见[预算](../../memoria/prompting/reader_budget.py)、[生产补检](../../memoria/memory/adaptive_retrieval.py)、[支持契约](../../memoria/memory/verification.py)。

## 3. 隔离实验与失败记录

显式LoCoMo `--deepseek-cache`使用另一个`deepseek-reader-input-prefix-v1`布局：Reader两条原始消息字节不变；核验仅在问题和完整证据列表相同时复用Reader**输入**，尾部追加独立任务，不带Reader输出或Gate判断。支持核验只需实际引用子集时保留原短请求，避免上下文和成本膨胀；未知/重复/伪造来源ID拒绝。

**生产独立核验布局与隔离实验布局不同。以下两题结果不是生产缓存收益、Claim/View收益或新LoCoMo全量成绩。** 新布局必须用[单独登记](https://github.com/ZJ331456/Memoria/blob/38648d3/eval/protocols/locomo-deepseek-cache-20261022.json)，原v3登记不能默许启用。只有同登记允许的布局是计划处理差异，其他输入SHA/模型/预算/并发要求仍核对，不混合续跑。
