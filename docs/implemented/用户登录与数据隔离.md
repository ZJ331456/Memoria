# 已实现：用户登录、数据目录与隐私边界

核对：2026-10-11。正式入口为 `memoria.api.create_app` / `main.py`，所有个人及共享业务请求先按登录账号选取独立运行时。核心路由工厂 `_create_tenant_app` 仅用于内部组装、OpenAPI 和工程测试，不是绕过登录的部署入口。

## 注册与登录

| 请求 | 行为 |
| --- | --- |
| `POST /api/auth/register` | JSON 为 username、password；成功 201，重复或预留名 409 |
| `POST /api/auth/login` | 返回 user、access_token、token_type、expires_in；同时设置登录 Cookie |
| `GET /api/auth/me` | 返回当前账号的服务端 ID 和 username |
| `POST /api/auth/logout` | 撤销当前令牌并删除 Cookie，204 |

用户名规范化为小写：3–32 位英文、数字、下划线，字母开头。密码 12–128 字符，数据库使用随机盐与 scrypt（N=2^17、r=8、p=1），不保存明文。此配置参考 [OWASP 密码存储指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。

登录令牌为 256 bit 随机值，有效期 12 小时；只保存 SHA256，退出后后续请求立即失效。本机重设密码撤销该账号全部会话。Cookie 为 HttpOnly / SameSite=Strict，HTTPS 下为 Secure；也可使用 `Authorization: Bearer <access_token>`。Authorization 出现时不回退到 Cookie，错误令牌不能借 Cookie 绕过验证。令牌是凭据，登录返回内容不要粘贴到聊天或提交。

登录/注册按账号每 10 分钟 10 次、来源 IP 每 10 分钟 30 次限流；密码计算最多并发 2 个。所有请求限制实际流式请求体大小，不能用 chunked 绕过 Content-Length。写请求检查 Origin 和 Sec-Fetch-Site；远程 API 访问必须 HTTPS，本机回环可 HTTP。默认只监听 127.0.0.1；远程部署需正确配置 TLS 及可信代理。

健康、接口文档、注册和登录可匿名访问，其余业务及 `/metrics` 必须登录。旧 X-API-Key 或单独 X-Agent-Key 不能获得用户身份。共享路由在登录后还需要该账号库中的 Agent key 与空间 ACL；不同登录账号之间没有默认共享。

## 数据目录和运行时

```text
data/
  auth/accounts.db                    账号、密码摘要、登录会话和限流
  config/models.override.toml          管理员默认模型配置
  users/<服务器生成的UUID>/
    memory/memoria.db                  会话、记忆、索引、审核、任务、情景及治理
    markdown/                         SELF / PENDING / MEMORY
    config/                           该账号 MCP、模型覆盖文件
    datasets/lccc-base/                原文、manifest、导入回执
    secrets/                          DPAPI 凭据、官方加密 OAuth profile
    reports/                          该账号 MCP 真实调用检查
  datasets/lccc-base/                  固定版本公开数据下载缓存
  reports/system/                     环境和迁移前检查
  legacy/pre-users/                   旧个人库、Markdown、配置备份（未导入）
  legacy/public-corpus/               迁移前公开语料库与回执
```

`[storage].database` 的父目录是 data root；网关不会打开原文件，也不会按请求中 user_id、username 或 X-Agent-Key 切换账号。会话、记忆、FTS、向量、来源、版本、候选、后台 worker、trace、情景、指标和 Markdown 全部从该用户独立库读取。用户 ID 只能由账号库产生，路径解析拒绝越界及用户目录符号链接。

用户不共享可修改的 Settings、Store、MemoryEngine 或 MCP Host。模型服务可共用权重和计算；HTTP 用户不能改写服务器模型地址、密钥或本机模型进程路径，`PUT /api/settings/models` 返回 403，防止把管理员凭据转发到其他地址。管理员在本机修改默认或该用户 config 中的模型覆盖文件后重启服务。最多常驻 32 个用户运行时，达到上限返回 503；该上限是资源保护，不是生产并发能力结论。

MCP 默认不开启。管理员对指定账号执行 configure_mcp 后才获得该账号配置；本机 GitHub 身份也是私有集成，不复制到每个新注册账号。飞书凭据使用 [Windows 当前用户 DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata) 加密；官方 OAuth token 由 AES 与系统凭据管理器保护，存储目录通过该账号独立 profile 指定，不能复用其他账号 token。当前只为 qin 配置了这三个 MCP。

## qin 账号与真实数据

qin 已在本机预留，公开注册无法抢占；没有设置默认或自动生成登录密码。在项目根目录自行执行并隐藏输入两次：

```powershell
.\.venv\Scripts\python.exe scripts/manage_users.py set-password qin
.\.venv\Scripts\python.exe main.py --host 127.0.0.1 --port 2237
```

在 `/docs` 的 auth/login 输入 qin 与刚设置的密码；随后 Swagger 的 Authorize 输入返回的 access_token，或同源浏览器使用登录 Cookie。`GET /api/sessions` 可见 50 段公开对话。`GET /api/datasets` 列来源清单，`GET /api/datasets/{dataset_id}` 返回原始 source ID 到消息 ID 的映射；其他账号看不到它们。

数据属于 qin 的项目空间，并不声称所有原话都是 qin 本人说的。说话者和事件时间仍未知；created_at 是本机导入时间。导入只写会话、原话、来源回执和消息 FTS，不自动造画像、记忆事实、标签或抽取任务。当前 50 会话、206 消息、0 memories，外键和完整性检查通过。重复导入验证所有原话；来源被改写/删除时拒绝再导入，批量失败整笔回滚。详见 [真实对话说明](真实对话数据与实验入口.md)。

## 本机文件保护与已知范围

`data/`、`config.toml`、`.mcp/`、模型和 token 不提交 Git。本机数据已设置 NTFS ACL，仅当前 Windows 账号与 SYSTEM；新建文件继承权限。管理员可再次核对/设置：

```powershell
.\scripts\protect_local_data.ps1
```

SQLite 和 Markdown **不是加密数据库**。HTTP 登录隔离不阻止同一个 Windows 账号直接读取文件，也无法防止系统管理员接管权限；磁盘丢失场景应另启用系统磁盘加密。当前没有账号删除/完整导出、MFA、端到端加密或多机租户调度；这些不算已实现功能。远程模型或外部 MCP 收到明确发给它的当前用户输入，登录隔离不能让第三方服务变成纯本地处理。
