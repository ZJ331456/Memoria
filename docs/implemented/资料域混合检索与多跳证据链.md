# 资料域混合检索与多跳证据链

2026-10-23。接在[来源片段绑定](来源片段绑定与回答稳定性.md)之后；个人 Claim/View、普通记忆与外部来源边界保持。实现为原生 Kernel 路径，不是 LoCoMo 专用检索器。真实长期理解、抽取 F1 和机制因果收益仍未验证。

## 资料域接入

[source_retrieval.py](../../memoria/memory/source_retrieval.py)由[统一搜索](../../memoria/memory/search.py)装配；`MemorySearch.memory_mode` 同时控制资料域的 `keyword / bm25 / dense / rrf`。TXT、DOCX 解析文本、笔记、任务结果和带归属头的连续对话都使用同一实现。原 `/api/library/search` 为旧词面查询；需要混合检索的消费者使用 `/api/memory-kernel/search`，资料回答使用 `/api/memory-kernel/knowledge-answer`。

```json
{"query":"Atlas 当时为什么选择快照方案，后来出了什么问题？","domains":["library"],"memory_mode":"rrf","limit":12,"budget_chars":8000,"use_adaptive_retrieval":true}
```

上例为虚构功能输入；`use_adaptive_retrieval` 仅用于 knowledge-answer。working 资料必须再提供本人创建的 `session_id`，不能借用别人的会话；账号由正式鉴权选择。

- **原文粒度**：带归属的资料按原始发言单元，普通文档按已有原文块。原文不改写、不当作账号本人的事实。词面检索使用实际正文；归属发言的 speaker 用于检索消歧，JSON ID 和日期字段不作为正文关键词灌入。英文使用既有NLTK Porter词形归一，减少opened/opening这类词面漏召；仅影响排名，不将词干作为实体/别名或事实，保留否定，中文不做英文词干化。
- **三路融合**：Keyword、BM25、Dense 分别排序后按 `weight/(60+rank)` 融合，权重 0.8/0.9/1.0；不直接相加 BM25 与 cosine，不将跨域轮转称为 RRF。2026-10-23后续修复在同一 `limit` 内保留至少一半RRF头部；其余名额先在各活跃通道top-4里轮转保护原RRF截断范围外的候选，再按RRF补齐。核心与互补项交错检查，重复候选不占多个名额，完全相同通道或单路模式保持原顺序。该机制只增加原话被检查的机会，不判断语义充分性；没有扩大limit、增加LLM重排或读取gold。
- **实际 BGE**：重用当前配置的 EmbeddingClient；每段按模型 tokenizer 无损切为至多512 token的向量子块，使用最佳子块相似度召回完整原文段，不用父向量平均值代替长文本检索。缓存命名空间包含模型/权重/Tokenizer指纹，缓存输入另含策略与完整正文 SHA。
- **有界索引**：同账号 SQLite 的 `library_vectors` 是可重建派生缓存，不是第二份事实库。查询先筛 active/current head/会话范围，再扫描至多2000段、160万字符；超限通过 `scan_truncated` 明示。首次本地查询补齐这一有限范围，后续复用；不批量重新调用旧资料的 LLM 形成。
- **远程费用**：本地 BGE 自动索引；HTTP Embedding 不在首次查询时偷偷批量建库。远程只查询已有同命名空间缓存；未索引时返回明确诊断，RRF 可退回词面，Dense 不冒充成功。显式 Python 索引须由宿主提供有限输入及调用账本，当前没有新增远程批量索引 API。
- **发布约束**：Embedding 等待后重查配置、来源版本、SHA、会话和撤回。跨批次维度/非有限值/零向量/缺段整体不提交该批构建。修订或撤回清除旧向量缓存；最终引用仍经过原 Kernel 依赖与支持核验。

`retrieval.library` 报告实际扫描、索引、Embedding尝试、Dense可用、退化、耗时及选择策略、互补保留数、截断数和各通道最终保留数。`candidate_selection`详细记录候选的原RRF名次、最终名次、保留理由/通道、至多64个被裁剪ID及截断标志；各路前32排序与相邻提示同样保留在捕获/自适应诊断。普通HTTP响应只放摘要并计入完整JSON预算，不把这些详细ID诊断注入Reader证据。低于2000字符的检索预算不再添加大段检索诊断。索引仍为有界 SQLite 扫描，不宣称已具备百万资料的 ANN 服务能力。

## 多跳支持

[query_plan.py](../../memoria/memory/evidence/query_plan.py)在看候选前冻结需求：原项目/采用/原因/结果，增加明确 both A and B 的各自事实与交集、事件持续时间的起止点、事件集合与去重计数、互补实例。最多8项；未识别的问法保留原问题总需求。这是有限规则规划，不是通用任意语言推理。

来源召回允许同一资料有多个互补原文段，取消统一入口原来的每资料最多两段限制。至多再取四段同版本相邻发言，分别保留作者、日期、SHA/span和引用。普通片段看前后各一条；以it/this/that/they/these/those及有限中文指代词开头的片段，优先看前一条、前两条和后一条，给跨一个追问的先行词一次机会。仍只扩前四个候选，总量不超`min(16, limit+4)`，边记录`turn_offset`及`semantic_link_verified=false`。相邻仅为检索线索，不能因此认定同一实体、因果或同一次事件；同名与多项目仍受原身份门控。跨资料只允许当前账号、原会话/条件/时间范围内的有界补检。

## 可选的机器图片描述文本输入

评测适配器`locomo_items(..., include_captions=False)`默认仍为原对话纯文本输入，审计记录非空`blip_caption`数量及实际导入/排除数量。只有显式开启时，已有BLIP描述才作为独立`#blip-caption`单元进入同一生产来源链；不读取图片、不调用OCR或图像模型。该单元作者明确为`machine image caption (BLIP)`，正文标明机器描述和父turn附件关联，末尾逐字保留原caption。父说话人只说明数据附件归属，不能当作caption作者或本人自述；`session_date_raw`为空、事件时间未知，不能用父会话日历伪造图片/事件日期。

这属于新的`locomo-dialogue-and-blip-caption-v2`输入协议，与默认`locomo-dialogue-text-v1`分开登记。新复测若使用caption，差异包含数据完整性变化，不能把全部分数变化归因于融合或Gate算法，旧纯文本历史成绩不改写。来源ID命中仍只是后验定位，不代表机器描述与本人原话具有同等可信度。

继续执行[一次缺项补检与闭合选择](缺项驱动补检与依赖闭合回答.md)：先区分缺失与未选，最多一轮两条补检；名称、事实、时间和条件所需引用完整进入 Reader。`selection.groups` 记录需求、原文引用节点、共同必要关系；这些关系是带原话校验的模型建议，不是现实验证的知识图谱。单题仍为8次总调用、240000 UTF-8输入字节、8000字符默认来源证据预算，包含完整Reader/一次格式重生成和支持核验预留，绝不读完整历史掩盖缺项。

Reader 明确区分“我的经历”和“我赞美/建议对方的经历”，收集互补实例；没有证据时不把相关话题写成本人行为。发布前独立支持核验及必要引用不放宽；同原话事件—日期的支持依赖现在单独留在 `adaptive.answer_support.support_dependencies`。计数没有足够事件、时间起点未知或身份冲突，仍保留未知/拒答。


### 候选、选证与回答归因

v8/v9的36个问题均实际Dense可用，无退化。v9后验26道有标注ID普通题，初始候选完整覆盖16道、补检后17道；v7为9/12道。Reader实际包完整覆盖10道，v7为8道。仍9道池内缺少部分ID（含1道官方不可见），5道已有ID但未到Reader。ID覆盖不是语义支持、必要组人工标签或自动真值。

v9最终16道未建立充分证据、3道答案支持未成立、17道校验接受；其中接受不等于答中所问具体属性。相关描述有支持却未回答具体类型/对象、部分正确实例代替所问实例、原问题人物/日期前提与原话不完全一致，仍是主要边界。不能仅因宽松Judge偏好一个答案就放行未知身份或补造事件。

同两段历史，v8形成372条批准、3辅助、2发布巩固头；v9为369/5/0。这些是随机模型输出下的形成产量，不是抽取F1、稳定巩固质量或真实长期效果。不能挑v8的巩固头数量来代表v9。

首轮工程发现两处回归：新原文索引丢了普通任务的既有审核反馈卡；原文优先排序挤掉完整巩固支持组。已恢复真实反馈依赖与普通文档/任务的完整巩固优先级，保留原断言，不删失败。另一次完整模拟48/49：保留期查询误当事件起止，消耗额外调用后碰到场景9次上限；已修正查询规划，场景/总请求上限和语义断言均未放宽。其138次已知调用、208758已知token和全部原始返回均保留。

最终完整功能模拟38场景49/49，134真实调用、204680已知token、206.350秒，零预算阻断/未知usage/执行错误，不写生产账号。个人BGE和新增资料域BGE四路均实际命中，Dense可用、无退化；完整工程回执与数据隔离核对见同批公开聚合的engineering字段。
