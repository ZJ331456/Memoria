## 第一阶段：来源约束的实体身份

SQLite新增memory_entities、memory_entity_aliases、memory_entity_mentions、memory_entity_cohorts和追加审计events。名称不唯一，UUID稳定，实体类型/账号私有库/个人或会话范围分别保留；不引入图数据库，不从向量相似创建身份关系。首版最多256个目录实体、每实体16个名称，明确来源绑定与人工/可信应用登记，不声称通用NER或自动实体消歧完成。

API复用正式账号网关：POST /api/memory-kernel/entities，GET /entities/{id}，POST /entities/{id}/aliases，POST /entities/{id}/revoke。请求不能指定owner。创建需要规范名的原样切片及conversation/library、source_id、revision_id、SHA、start/end/quote；会话角色、公开语料排除、撤回、资料当前修订和scope核验。新增和别名是明确的目录操作，不把名称登记变成本人事实或自动批准Claim。

别名独立行，须提供“规范名又名/也叫/简称…别名”等有限肯定原话；完整锚定该句，否定、相似、共现或指令不批准。相对描述如“我的长期记忆项目”只能登记在明确会话范围；工作资料不升级为全局。新增别名/撤回有expected_revision和事务；新建同名实体保留两个ID，读取遇到多个有效身份返回ambiguous，不自动合并。匹配保留原文字符位置及英文词边界，有限NFKC/casefold不伪造原文。

新Observation、LLM已批准普通记忆/Pattern和资料已核验Observation自动关联目录中已有、唯一且当前有效的实体。mention保留domain/target/revision/role与原话Anchor，不以浮点confidence代替证据。实体不是槽位事实，关联也不表示所有权或因果；旧正则entities_json和related图边不转为事实关系。

跨会话Pattern在原主题/条件/极性基础上按实体身份集合分组，过滤发生在候选LIMIT之前。资料观察group保留实体集合，原文/反馈/主体审核继续执行。实体、别名证据或来源失效使既有绑定退出，Pattern/资料巩固不得复用失效实体；不重写不可变观察或旧版本，不批量重处理旧个人历史。未登记名字仍保留原文/原有主题边界，本阶段不声称它已获得跨资料稳定身份；目录登记后需显式重新形成旧资料。

## 第二阶段：可关闭的实体召回

系统配置memory.retrieval.entity_enabled默认false，QueryRequest/MemorySearch.use_entities可逐请求覆盖；entity_type限定目录匹配和实体通道，不保证原三路候选都具有该类型身份，也不是权限过滤器。实际私有配置不修改，只更新system.example.toml。普通记忆rrf在原Keyword/BM25/Dense之外增加entity排名，权重0.8/(60+rank)，每个父记忆一票，不叠加别名次数或模型confidence；实体种子在全局扫描LIMIT之外补进候选池。纯keyword/bm25/dense仍是原方法。

资料新增/修订与普通Engine写入/纠正也接原文实体索引，长文本按有重叠的原文片段索引；旧资料不偷偷批量回填。资料域在原词面与实体候选之间做排名融合，保留原词面互补片段与跨域round-robin，不声称文档已具备Dense四路。已核验资料主体命中唯一目录身份时用稳定entity ID参与巩固，原主体证据仍保存；source-formation-v6避免复用旧分组缓存。

同名歧义拦截实体访问，显式类型可缩小候选；历史as_of不启用实体扩展，避免后来别名进入旧时刻。实体有命中时关闭旧related图扩展，防止将启发式关联混为实体证据；同预算实验须两侧都关闭图扩展控制变量。无目录/无实体命中不伪造第四路成功。

召回候选携带entity_rank和entity_dependency；查询解析、关联来源及目标修订在Embedding等待后、证据选择后与Reader发布前复核。目录/别名/来源/版本变化会撤销旧证据，不恢复缓存文字。API依赖先验实体，再验原记忆/资料快照；实体水位加入memory_trace，不改变Claim当前事实裁决。此功能不是通用身份消解、自动事实关系或质量收益证明。

## 第三阶段：固定预算的实体对照

入口[scripts/evaluate_entity_retrieval.py](../../scripts/evaluate_entity_retrieval.py)，协议[entity_retrieval.py](../../memoria/experiments/entity_retrieval.py)，固定输入[entity_inputs.json](../../simulation/entity_inputs.json)与后验[entity_expectations.json](../../simulation/entity_expectations.json)分开。8个虚构场景、3方法，共24记录；这里直接写入带原话来源及实际BGE向量的工程夹具，不评价LLM抽取/审核质量，不使用生产历史或真实用户。

| 方法 | 行为 |
| --- | --- |
| three_lane_rrf | 原Keyword/BM25/Dense加权RRF，关闭实体通道 |
| entity_filter | 对基线返回候选按已知实体身份过滤，保持原顺序；无身份命中保留开放检索，同名歧义澄清；不能补回基线未召回的证据 |
| entity_rrf | 原三路加实体第四路并做排名融合，原三路仍可能有无身份或不相关主体候选；不等于硬实体过滤 |

三者同一库、来源前缀、候选上限8、Top-K上限4、evidence_coverage、关闭旧图扩展；选择器证据JSON字符上限默认8000，别名桥接/依赖/选择器元数据都计入该预算。Reader系统/查询/引用目录等另通过原完整上下文预算和CitationGuard，不复制另一套提示/评分器；远程模型精确Tokenizer未知，因此是同选择器字符上限对照，实际tokens另报，不声称总请求等Token。共用Embedding预热，按场景轮换方法顺序，记录预热、检索/选择与模型调用耗时；本版未单列索引构建时间，也不是正式生产吞吐或延迟基准。
