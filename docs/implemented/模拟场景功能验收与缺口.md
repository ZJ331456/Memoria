## 验收方法

27组、34个问题检查覆盖12槽位、形成/审核、条件、角色/主体、否定、未来/敏感/注入、Claim/View、冲突/撤回恢复、支持组、跨会话Pattern、外部资料、反馈、资料修订及三资料巩固。真实调用使用现有deepseek-flash；默认禁用Embedding的隔离词面协议，不能冒充当前BGE生产配置的质量对照。另使用真实本地bge-small-zh-v1.5验证3条直接录入检索夹具及长文本，明确不是LLM自动批准的记忆。

双时间、人工修订发布/回退、条件/TTL/临时会话、不可变记录、expected revision、完整支持组、DOCX/TXT解析、预算、恶意/越界引用、失败分母、租户/渠道入口及事务由完整工程测试覆盖。模拟LLM检查与工程替身分开记录；不宣称每项都经过真实模型、外部机器人或长期连续人物验收。

每个问题单列：生产执行状态、路径/答案、来源前缀、观察、审核、实际批准Claim/普通记忆/Pattern、候选/引用与失败原因。断言分为安全约束和目标能力，安全拦截不自动算能力完整。原始调用全部留账，默认0自动重试，执行错误保留分母；输出文件全部在Git忽略的simulation/runs，不放真实账号生产库。模拟run标记synthetic_functional，原研究归因/LoCoMo入口不接受其为正式成绩。

## 已定位和修复

| 问题 | 改动与实际验证 |
| --- | --- |
| LLM因冲突返回Supported+review，却继续使用旧View | 独立证据、风险与原话检查均通过且存在单值冲突时记录受约束修订提案；保持待审，不覆盖事实。当前读取/Reader原门禁识别它，撤回后退出。实际复测冷查询/冲突澄清/撤回恢复三项通过 |
| “不喝咖啡”已形成负向Claim，但忌口查询被当未知肯定状态 | AccessRequest增加constraints_only，统一路由和CitationGuard新鲜度重验共用否定意图规则；只读已批准负向约束，不把“不住A”推成住B。实际忌口Reader与引用通过；正向未知仍澄清 |
| 同一技术主题被拆成入门/维护/性能、interest/behavior或“本次请求”scope | 观察器获得最多16组既有标签供语义一致时复用；仅作为低信任候选，当前原话仍须独立支持，完整多来源与审核门槛不变。实际3会话形成1个有界Pattern，未变成本人Claim |
| 项目被当unknown主体，反馈被误作主原文 | 提示明确项目/组织可作主体，主quote与feedback_quote分开绑定；原样位置/主体/反馈及独立审核继续强校验。同条件三资料形成1条巩固记忆，任务反馈最终通过 |
| 来源Reader选择元数据内citation导致整体拒绝 | 明确只允许每个最外层evidence.citation；嵌套定位ID不单独可引。保持原严格拒绝和依赖检查，不将任意模型ID加入白名单。任务反馈最终实际回答通过 |

策略版本分别更新为memory-auto-review-v3、formation-v2-topic-context、source-formation-v4-entity-feedback；不自动批量重处理旧资料。主题候选只是有限标签复用，没有实现通用实体合并或自由条件归并。

真实BGE：3条直接录入夹具，其中一条有120段运行记录及尾部恢复步骤；Keyword、BM25、Dense、RRF均召回目标父记忆。Dense/RRF诊断embedding_attempted/dense_available为true，没有降级冒充Dense成功；0远程LLM。该例有共同词面与小库，不能证明一般检索质量、英中召回或性能收益。

## 尚未通过的两项

1. 条件自动发布：复杂默认/面试例外被抽出3观察、3候选，但生产主审风险门槛仍保留待审；未自动形成3条条件Claim。下一步需把原有ConditionParser/条件证据绑定接入自动准入，分别核验每条局部证据、继承边界及临时生命周期，不能仅移除complex_condition拦截。
2. 自动强化的来源接线：第二条同值自述获批时只复用旧Claim，未向Claim加入独立批准支持组；撤回首源会失去当前状态。底层手工支持组存在，但不能因此宣称生产强化完整。下一步必须同时处理每组来源及关联普通记忆的依赖，防止只增加消息ID却继续被首条父记忆失效绑定，或反过来绕过用户撤回。

因此目前不能称“所有核心模块在真实使用中都正常”。本批交付可重复的覆盖清单、原始失败、定向修复和明确缺口；不新增LoCoMo评分，长期效果与抽取F1仍待获准真实连续资料与独立标签。
