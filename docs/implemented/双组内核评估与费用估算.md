## 只比较两组

| 组 | 在线输入与处理 |
| --- | --- |
| Baseline / raw_context | 完整可见历史放在问题前，由同一模型直接答；完整请求超过字节/可核验窗口预算时删除最早整轮，记录丢弃量与首尾保留ID |
| Memoria / memoria | 相同历史按session切成最多12,000字符的外部来源窗口，经原生形成/独立审核/有限巩固后，调用原生 `Kernel.answer(KnowledgeAnswer)` 完成检索、缺项补检、Reader与发布校验 |

Chat、机器人和文件上传是接入方式，不是额外实验组。此处适配器仅改变公开对话的输入格式，不另写Reader或降低内核准入。LoCoMo多人物原话的作者不是账号本人，必须标记external/working；不能同时写成本人消息和本人资料，不能为激活Claim/View伪造身份。

两组共享DeepSeek Flash非思考、temperature=0、top_p=1、Reader最多1024输出、120秒超时、0隐藏HTTP重试。v1提案原并发2为两组并行；本次正式v3改为方法先后、方法内最多8段独立历史，各历史题目顺序执行，见文末登记。完整请求上限240,000 UTF-8字节，内核证据上限8,000字符；远程没有精确Tokenizer时不虚报精确Token窗口。内核内部规划/支持等额外调用属于被测框架，完整计费。这是框架整体比较，内部提示与策略不同，不能把差值直接归因于某一个机制。

资料域仍使用现有原生来源检索。个人Dense/RRF、个人Claim/View没有因为这个适配器就自动参与所有LoCoMo题；必须根据实际路由和形成回执报告覆盖，不能把旧PrefixRetriever分数追认为完整内核收益。

## 修正了哪些评估漏洞

- Baseline原先从尾部删记录，实际保留最早历史；现按声明丢最早整轮，并计入system、问题、序列化和输出预留。
- 原Memoria组自行search后另写Reader，现仅调用生产Kernel.answer，保留原引用/支持/版本发布检查。
- 原公共对话重复写入且冒充self/personal，现只保留外部来源，原始speaker、ID和未声明时区的raw session日期留在正文，不伪造可信UTC。
- 历史签名包括正文、角色、日期等全部可见输入，不再仅比较ID；不同历史隔离数据库保留失败现场，不删除取证信息。
- working资料与Reader绑定同一隔离会话，原生内核联调用例验证来源可读及最终发布，不只检查接口替身。
- 预算、供应商或输出契约失败标为执行错误，不交给Judge算作对抗题正确拒答；无法解析Judge返回标为judge_unknown。
- 形成失败按来源前缀记错，不对每道题偷偷重试整个形成批次；原生观察/主审失败与读取失败分别留痕。
- 第5类官方QA没有answer字段，使用拒答参考，不读取adversarial_answer；全部1,986题都保留。
- 相同题数还必须具有相同题ID才可比较；失败与unknown评分留在计划分母。`accuracy=correct/planned`在覆盖不完整时是保守下界，分开报告scored/errors；评分不完整不发布精确delta。
- 形成、审核、巩固、Reader、支持、修复、独立评分全计入私有calls账本；缺失usage不补零。按阶段拆费，独立评分不混作推理成本。
- 默认仅估算；实际执行须同时有execute、allow-remote、正的调用/美元费用上限，核对原始输入SHA、模型、输出/字节预算与评分提示SHA。客户端按冻结高峰价格保守预留，未知usage保留预留；这不是供应商硬账单上限。

逐题summary.latency_ms目前是回答阶段（内核含实际检索/支持），不是形成费用/时间的完整摊销值；形成和评分的LLM耗时留在分阶段账本，整个运行墙钟在manifest。小批校准时再补每组形成摊销与串行/并发口径，不把回答阶段均值直接叫全生命周期单题延迟。

## 二分类评分口径

参考本机 [mem0ai/memory-benchmarks固定版本](https://github.com/mem0ai/memory-benchmarks/blob/4b61c5d31b9c668a12b4f5e78064248a02c82d2b/benchmarks/locomo/prompts.py) 的独立CORRECT/WRONG评分。保留宽松列表部分命中、释义、日期±14天/时长±50%容差，补充主体和拒答要求，属于**适配版**，并非原Mem0分数精确复现。此指标不等于严格事实完整性或人工正确率。

主分为1–4类1,540题；第5类446题作为独立的对抗拒答二分类补充，不并入主分冒充同口径。新LLM评分不是旧Token F1或拒答短语命中率，旧数字不能横向抄到新表。Judge仅在回答后接收问题/gold/答案，不见组名；gold及标注证据ID不进入在线写入、检索或回答。
