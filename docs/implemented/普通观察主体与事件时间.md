2026-10-21。对话 Observation 和资料 Observation 共用 [observation_semantics.py](../../memoria/memory/observation_semantics.py) 的语义记录，接入原生产 Kernel、worker、独立审核、检索、Chat 上下文和 Reader。没有把所有观察转成 Claim，也没有批量重新抽取个人历史。

## 时间定义

| 字段 | 含义与来源 |
| --- | --- |
| `event_time` | 当前原话中所述事件或计划的时间区间；无法定位时为 null |
| `time_precision` | exact / day / month / year / range / unknown；周用 range 表示 |
| `source_time` | 原始来源时间，允许未知；来源声明、平台事件、即时接收分别标明依据 |
| `source_recorded_at` | 消息或资料版本实际进入系统的时间 |
| `recorded_at` | 本条 Observation 实际形成并保存语义记录的时间 |

原始来源、来源入库和观察形成分别保留各自含义。新导入历史对话和旧资料不会倒写 `messages.created_at`、资料修订时间或 Claim 的 recorded time。重放器的 `original_time` 只作为明确声明的原始来源时间。

例如，一份资料今天上传，声明原始资料时间为 `2023-01-02T10:00:00+08:00`，正文写“Memoria昨天完成了配置校验”：事件时间可依声明解析成 `[2023-01-01T00:00:00+08:00, 2023-01-02T00:00:00+08:00)`，source time 保留 2023 年的声明，两个记录时间保留本次真实入库和形成时间。声明不是独立核验的现实时间，回答需保留“依据来源声明推算”的边界。

同一资料不提供原始时间时，事件时间保持未知；上传时间、文件修改时间、Word 文件属性和模型推测都不会自动补为原始时间。

`source_time_basis` 的取值：

- `platform_event`：飞书 create_time、QQ timestamp、Telegram date，经过已有渠道解析和账号绑定后进入相同核心；平台 epoch 按项目中文时区即东八区表示。
- `live_received`：新 Chat/API 消息即时进入服务的观察时间，明确标记接收依据。不是为旧消息回填的日期。
- `declared_original`：调用方在导入/重放时明确提供的带时区原始时间，不冒充独立身份或时间认证。
- `unknown` / `legacy_unknown`：本次未声明或历史记录没有可核验依据。

机器人缺少平台时间时保持未知。助手回复不会继承对应用户消息的平台时间。原始时间有明确时区时，相对日历运算保留该时区；中文绝对日期及默认查询沿用项目原有东八区定义，ISO 精确时间保留原偏移。

## 主体、角色与认识状态

| 字段 | 当前行为 |
| --- | --- |
| `subject_ref` | 当前本人自述为 self；已有目录中唯一、有效的原文实体可用 entity:ID；已核验叙事先行词保留 memory:/message: 引用；资料中的未登记名称限定为 source:来源ID:名称摘要；其余 unknown |
| `source_role` | 从可信入口及资料类型派生 user / assistant / system / tool / external / self_document / task_report / unknown_document，模型不能自行提升角色 |
| `epistemic_status` | explicit_statement / source_assertion / reported / plan / hypothesis / question / unconfirmed，区分来源陈述与推断边界 |
| `event_status` | asserted / planned / negated / hypothetical / question / unknown，计划和未完成不会被自动标成完成 |
| `condition_scope` | 保留原条件标签、有限类型约束、是否已识别或未知，继承条件保留独立原文位置 |
| `evidence_ref` | 当前来源 ID、版本、SHA、字符区间、原样片段及 fact / event_time / subject / condition 用途 |

历史关联提案中的 `subject_ref` 继续执行 ID 白名单与独立核验；最终规范主体位于 `semantics.subject_ref`。历史内容只用于消歧，新的事件证据仍必须来自当前来源。同名资料主体不会仅凭名字或向量相似度注册为同一全局实体。

一次查询行为的主体可以是发起本轮交互的用户，认识状态仍是 unconfirmed；这不证明稳定偏好。涉及他人的对话观察不发布为账号本人事实；主体不明时保留未知。工具消息也不能自行声称 `tool_verified`，当前任务结果属于报告，缺少独立执行凭据时不提升为已验证事实。

Pattern 巩固在原类别/主题/条件/极性、实体和叙事约束之外，加入主体与事件模态分组，并在 LIMIT 前过滤。问题和普通未确认交互同属 nonassertion；计划、假设、明确事实分别保留。原始状态字段不被分组标签覆盖。

## 抽取与审核

模型可以提供可选 `temporal_quote`，供程序定位同一句中包含当前 fact quote 的连续时间上下文。它必须唯一绑定所选原文位置，不允许跨句/段借标题日期、别的事件或自由补写日期。文档分块允许原文在其他块重复，仍按当前选定块的全局 Span 核验；CRLF 只做原有无损映射。

时间由共享 [TemporalResolver](../../memoria/memory/temporal_resolver.py) 计算，不接收模型自算的 ISO 日期作为事实：

- 中文年/月/日、带时区 ISO 精确时刻；完整两端日期的日历区间。
- 有明确原始来源时间时，支持今天/昨天/前天、上周/本周/下周、上个月/本月/下个月、去年/前年及有限数字年前等。
- 一周按周一至下一周一；日历区间两端按所指日/月/年的覆盖范围保存为半开区间。
- 多个不相容时间、缺原始时间、非法日期、缺时区精确时间、省略年份的区间端点、最近/上次等保持未知，保留原因。

共享 EventTime 定义不改变 Claim 的准入：月/年区间不会被转换成精确 fact_start，状态纠正和迁移仍受原证据/条件/版本协议限制。

对话独立主审继续检查 `time_supported`。已明确本人、日期有原文和来源时钟依据、独立模型核验通过的低风险普通经历，可作为有界普通记忆发布；计划保留 planned，明确未完成保留 negated。状态槽位和未知时间不借此绕过原审核，假设或问题不能发布为事实。

资料独立审核同时看到程序的时间提案和来源时钟；已解析时间须显式返回 `time_supported=true`，缺项或不支持进入辅助状态。条件只描述原文施加的场景限制，时间信息、外部真实性未验证与条件未知分别处理。模型 NLI 判断不构成现实核验。

## 存储、访问与失效

新增同账号 SQLite 表 `memory_source_clocks` 与 `memory_observation_semantics`。记录按来源版本或 Observation ID 绑定，触发器禁止更新及删除重建活跃记录；原始来源删除后级联清理。旧数据没有证据时保持未知，不生成新的真实日期或自动补抽。

- `GET /api/memory-observations` 返回完整 `semantics`；资料详情的卡片 provenance 和生产 lineage 也可回查。
- 普通 MemoryEngine 检索结果、工具召回、Chat prompt 和生产 Reader 携带预算内的时间/主体摘要；完整原文、SHA 与审计仍在原记录中。
- 明确的第一人称事件历史问句，例如“2023年3月我交付过什么模块？”，进入原统一 Reader。按事件区间过滤、缩到相应原话证据；未知/超出范围的事件不会因刚入库而进入过去的事件结果。一般建议、病因咨询等仍走普通 Chat。
- `MemorySearch` 支持 `event_start` / `event_end`、`recorded_as_of`、`subject_ref`；事件区间必须提供两个带时区的有序端点。参数在 `/api/memory-kernel/search` 使用，资料 Reader 沿用同一检索契约。
- recorded cutoff 排除之后才记录或改动的来源/版本/观察。当前为保守过滤，不能重建任意历史时刻的整个普通记忆库；原 Claim 双时间查询继续独立负责状态历史。
- 确定性事件过滤要求来源的完整不确定区间包含在查询范围内。只有年份的证据不能证明发生在该年某个月；仅相交、未知或范围不符时不足以列为目标时段事件。区间也不证明持续状态或精确时点。普通事件的日期不等于普通记忆的发布/失效区间。
- 选择与 Reader 之间再次验证 Observation 引用、实体/叙事依赖及来源，撤回或变更后拦截。观察因巩固保留期进入 archived 时，仍受支持的普通长期记忆保留其事件日期；撤回和归档含义分别处理。

```json
{
  "query": "Memoria工程检索配置校验",
  "domains": ["library"],
  "event_start": "2023-01-01T00:00:00+08:00",
  "event_end": "2023-02-01T00:00:00+08:00",
  "budget_chars": 8000
}
```

纯文本/Word DOCX 文件导入复用 `/api/library/import`，增加可选查询参数 `source_time`；`+08:00` 中加号须正常 URL 编码为 `%2B`。JSON SourceInput 和 RevisionInput 使用相同字段。修订不继承旧版本的原始时间，调用方有依据时再明确声明。PDF、图片和 OCR 仍未实现。
