# 配置目录与模型后端

更新：2026-10-16。配置入口集中在根目录，运行数据仍在data；服务器级私密配置统一到`configs/local/`，账号覆盖与加密profile保留独立。模型参数由文件加载，没有把当前模型或密钥内置到业务代码。当前LLM主审/人工辅助策略不因本轮配置整理改变。

## 1. 文件各自负责什么

```text
Memoria/
  config.example.toml                  # 公开系统配置示例，引用模型模板
  config.toml                          # 本机系统配置：端口、存储、预算、worker等；忽略
  configs/
    models.example.toml                # 公开模型参数与不同后端示例
    research-*.toml / research-*.json   # 冻结研究角色/协议，不作为生产模型配置
    local/                             # 全目录Git忽略，默认由ACL工具保护
      models.toml                      # 本机服务器默认main/fast/embedding
      feishu-bot.json                   # 机器人启用状态
      feishu-bot.credentials.dpapi      # 应用凭据，Windows当前用户加密
      backups/                         # 配置迁移前副本，不进入Git
  data/
    auth/accounts.db                   # 正式登录账号
    users/<UUID>/config/models.override.toml  # 该账号的模型覆盖
    users/<UUID>/secrets/               # 该账号DPAPI profile / OAuth
    channels/feishu.db                  # 绑定与消息状态；仍是数据
    users/<UUID>/memory/                # 本人会话、记忆、审核、索引等
  model/bge-small-zh-v1.5/              # 真实本地权重，不随Git下载
```

根目录可以同时有`config.toml`与`configs/`：前者是系统入口，后者管理模型模板/本机配置/研究登记。私密文件通过忽略目录保存；账号资料维持UUID边界，不把某人的DeepSeek Key合并为全体用户默认值。

本轮已将原`data/config`的管理员模型覆盖、机器人启用/加密凭据及唯一历史配置备份迁入上述目录。账号覆盖、DPAPI profile、OAuth、会话、记忆与绑定不搬动。迁移有独立备份与失败回滚；既有加密文件按字节保留，没有解密后写成公开配置。

## 2. 加载顺序与如何找实际模型

1. 读取`config.toml`（或`--config` / `MEMORIA_CONFIG`指定文件）；`extends`继承系统设置。
2. 读取其中`[models].file`指向的模型文件，覆盖早期inline模型槽位。显式路径缺失会报错；不会悄悄换成另一个模型。
3. 正式登录后再应用当前账号的`models.override.toml`；`credential_profile`只从该UUID的secrets加载，核对账号/模型/端点绑定。

`models.file`和`configuration.private_directory`相对**声明它们的配置文件**解析；本地模型`model="model/..."`仍相对项目根目录。模板默认引用公开`configs/models.example.toml`；正式管理员应复制到忽略的local目录后改根引用。

从仓库根使用项目venv查看，不生成、不展示Key：

```powershell
# 管理员默认；不是登录账号覆盖后的值
.\.venv\Scripts\python.exe scripts/configure_models.py show
# 当前已有账号的实际值与配置路径
.\.venv\Scripts\python.exe scripts/configure_models.py show --user qin
```

输出包含模型、base_url、backend_kind、device、thinking、Key是否已配置与来源路径，没有Key内容。`show`不会测试网络或调用模型。HTTP业务用户仍不能修改服务器模型/凭据/进程路径；`PUT /api/settings/models`在正式网关保持403。本机管理员修改文件后重启服务，不能假定编辑文件已刷新常驻运行时。

## 3. 新机器准备独立模型文件

```powershell
# 已有文件不覆盖
if (-not (Test-Path config.toml)) { Copy-Item config.example.toml config.toml }
New-Item -ItemType Directory -Path configs/local -Force | Out-Null
if (-not (Test-Path configs/local/models.toml)) { Copy-Item configs/models.example.toml configs/local/models.toml }
# 然后在config.toml中将[models].file改为 configs/local/models.toml
.\scripts\protect_local_data.ps1
```

根配置中的引用只需要：

```toml
[configuration]
private_directory = "configs/local"

[models]
file = "configs/local/models.toml"
```

原来的`[llm] request_timeout_seconds/max_retries`、`[agent]`、`[memory.worker]`、`[server]`、`[storage]`继续留根配置。模型文件仅接受llm.main、llm.fast、memory.embedding，错误字段、后端/角色组合会在加载阶段失败。原`[llm.vl]`没有业务消费者，本次模板与本机迁移不再保留该无效槽位。

## 4. LLM：远程API与本地OpenAI格式

两者均用`backend="openai"`，客户端统一发送`messages/tools/max_tokens/stream`等受支持的Chat Completions子集。

### 远程API

下面整表放入私密模型文件；模型ID须按实际账号可用值填写，main与fast可独立选。示例ID/端点来自本机已有DeepSeek配置，不是所有供应商的默认。

```toml
[llm.main]
backend = "openai"
model = "deepseek-flash"
base_url = "https://api.deepseek.com/v1"
api_key = "${MEMORIA_LLM_API_KEY}"
thinking = "disabled"

[llm.fast]
backend = "openai"
model = "deepseek-flash"
base_url = "https://api.deepseek.com/v1"
api_key = "${MEMORIA_LLM_API_KEY}"
thinking = "disabled"
```

`thinking`只有官方DeepSeek HTTPS端点支持；其他兼容服务和本地LLM省略此项。当前已配置账号的disabled保持，没有开启思考。不配置fast槽位时，preferred_chat_model在辅助任务回退main。

环境变量由启动业务的同一终端继承，私密输入：

```powershell
$taskModelKey = Read-Host 'LLM API Key' -AsSecureString
$env:MEMORIA_LLM_API_KEY = [System.Net.NetworkCredential]::new('', $taskModelKey).Password
Remove-Variable taskModelKey
.\scripts\cmd\start_backend.cmd
```

账号已有DPAPI profile时继续使用，不重输或复制为全局Key。Embedding API使用自己的Key/环境变量，不自动借用LLM凭据。覆盖中切换端点时不会继承旧端点的Key/thinking；完整配置中显式写入的Key由本机管理员负责匹配端点。

### 本地OpenAI兼容LLM

```toml
[llm.main]
backend = "openai"
model = "model/Qwen3.5-2B"
base_url = "http://127.0.0.1:8080/v1"
api_key = ""
```

model必须匹配本地服务公布的ID；`api_key=""`只适用于不要求Key的回环服务，有鉴权则配置真实Key。客户端为无Key回环发送`Bearer local`占位。base_url填根路径，客户端追加`/chat/completions`；不要将完整生成接口填作base_url。

本项目已有本机服务可选：

```powershell
.\.venv\Scripts\python.exe scripts/serve_local_llm.py --model model/Qwen3.5-2B --device cuda --port 8080
# 在另一个终端启动2237业务；模型服务与业务是独立进程
```

保留既有进程内LLM选项`backend="transformers"`、model路径、device=auto/cpu/cuda；主要接入推荐统一OpenAI HTTP。旧账号`local://...`文件可继续被解析，未新增其他本地推理引擎。

## 5. Embedding：本地BGE或API

### 进程内BGE（当前本机）

```toml
[memory.embedding]
backend = "bge"
model = "model/bge-small-zh-v1.5"
device = "auto"
```

自动选择CUDA或CPU，也可明确指定。模型只能从本地加载，torch/transformers延迟导入、禁止远程代码和自动下载。当前本地支持BGE small v1.5中文512维，原LoCoMo英文384维路径保留；不宣称支持任意Embedding架构。已有块/指令/来源校验规则保持，新的backend/device写法规范化到相同运行地址，设备/Key不改变向量namespace。

model路径、权重与tokenizer指纹改变才会使用新的空间；不要将不相容向量混合。单块tokenizer上限和Reader预算仍是不同约束，见[本地BGE](本地Embedding配置.md)。

### OpenAI兼容Embedding API（含回环服务）

替换整个embedding表，不同时保留BGE的device：

```toml
[memory.embedding]
backend = "openai"
model = "你的Embedding模型ID"
base_url = "https://你的Embedding供应商/v1"
api_key = "${MEMORIA_EMBEDDING_API_KEY}"
```

回环服务可用`http://127.0.0.1:8080/v1`，无鉴权则Key留空。发送`/embeddings`、input数组和float格式，验证向量数量、索引、维度、有限数值及非零。不同供应商的tokenizer/长文限制不相同；通用API不自动假定其使用BGE分块器。

## 6. 显式连通性检查

```powershell
# 实际本地BGE编码，会加载本机权重
.\.venv\Scripts\python.exe scripts/configure_models.py test --user qin --slot embedding
# 远程检查需明确允许，发一条短ping，可能收费；不要当质量评测
.\.venv\Scripts\python.exe scripts/configure_models.py test --user qin --slot main --allow-remote
```

未选user即检查管理员默认。检查回环服务不需allow-remote；HTTP200还要检查所选响应协议，不能把任意成功页面当向量/聊天结果。失败不回显供应商原文中的请求/Key，输出模型错误类型/状态及通用提示。LLM响应同时给finish_reason与completed_generation；短探测达到length仅说明连通，不算完整回答。

## 7. 旧本机布局迁移

已有本机环境由本轮完成；其他旧部署在备份并停止后台后明确执行：

```powershell
.\scripts\cmd\stop_backend.cmd
.\.venv\Scripts\python.exe scripts/migrate_config_layout.py --config config.toml
.\scripts\protect_local_data.ps1
.\scripts\cmd\start_backend.cmd
```

检测到未迁移的旧data/config时，正常启动会明确报迁移提示，避免静默换模型或丢机器人配置。迁移保留非模型设置、环境变量引用和原始配置备份，私有配置写入采用临时文件替换。只处理已知服务器级文件，未知目录项、链接、越界和已有目标拒绝覆盖；失败逆序恢复移动并逐字还原根配置。`data/config`仅在已为空时删除，不递归删除数据。账号覆盖/秘密不扫描迁移、不复用给其他用户。
