# 配置目录与模型后端

更新：2026-10-16，以用户最新要求的“四类各自统一”布局为准，替代前一轮根入口+configs/local方案。没有local子目录，模型参数没有内置到业务代码。

## 1. 四类配置

```text
Memoria/
  config/
    system.toml / system.example.toml   # 系统/HTTP/数据库根/记忆策略/预算
    models.toml / models.example.toml   # main、fast、embedding及账号专属槽位
    bot.toml / bot.example.toml         # 飞书/QQ/Telegram启用/加密凭据/代理
    mcp.toml / mcp.example.toml         # 全部服务定义/各账号启用
    README.md
  data/
    secrets/feishu-bot.credentials.dpapi   # 当前Windows用户加密应用凭据
    users/<UUID>/secrets/                  # 本人的模型profile、MCP应用凭据和OAuth
    users/<UUID>/memory/                   # 本人历史、记忆、审核、索引
    channels/feishu.db                     # 绑定、队列、锁；属于运行数据
    backups/configuration-*/              # 本次迁移前文件与旧配置归档
  eval/protocols/                          # 冻结实验参数，非生产配置
  .mcp/                                   # 本机安装的MCP程序
  model/                                  # 本地模型权重
```

只提交四个example和说明；四个实际TOML、密钥、OAuth、数据库和权重均忽略。system配置中的storage.database父目录仍决定数据根，移动配置文件不会创建新的账号库。相对模型/数据/技能路径继续以项目根为基准，配置文件位置不改变向量空间。

## 2. 准备与加载

从项目根执行，已有文件不覆盖：

```powershell
Get-ChildItem config/*.example.toml | ForEach-Object {
    $taskConfigFile = $_.FullName.Replace('.example.toml', '.toml')
    if (-not (Test-Path -LiteralPath $taskConfigFile)) {
        Copy-Item -LiteralPath $_.FullName -Destination $taskConfigFile
    }
}
.\scripts\protect_local_data.ps1
.\scripts\cmd\start_backend.cmd
```

默认入口config/system.toml，读取同目录models.toml、bot.toml、mcp.toml；四个必须齐全。全新仓库尚未准备实际文件时，Python加载默认值可读取完整example组，后台启动脚本仍要求实际文件。显式--config或MEMORIA_CONFIG不存在会报错，不静默换成模板。旧根config.toml存在时要求先迁移。

单独的实验/工程配置可用显式--config隔离inline槽位，不发现生产私密模型。extends仅用于这些显式TOML的系统/inline继承，不再承接models.file/private_directory。旧分散生产布局必须显式迁移，无长期双轨读写。

## 3. 模型：API和本地在同一文件选择

修改config/models.toml，不同时保留重复表。main为对话/Reader，fast为可选辅助槽位；fast未就绪时按原逻辑回退main。

### 远程LLM

```toml
[llm.main]
backend = "openai"
model = "你的实际模型ID"
base_url = "https://你的供应商/v1"
api_key = "${MEMORIA_LLM_API_KEY}"
```

main/fast可分别设置。官方DeepSeek端点可显式thinking="disabled"或"enabled"，其他兼容端点省略；本机已配置账号保持disabled，未开启思考。

### 本地OpenAI兼容LLM

```toml
[llm.main]
backend = "openai"
model = "model/Qwen3.5-2B"
base_url = "http://127.0.0.1:8080/v1"
api_key = ""
```

model须匹配本地服务ID；无Key仅用于无鉴权回环服务，实际请求发送Bearer local占位。独立启动模型服务，再启动2237业务：

```powershell
.\.venv\Scripts\python.exe scripts/serve_local_llm.py --model model/Qwen3.5-2B --device cuda --port 8080
```

两种HTTP模式同走OpenAI兼容Chat Completions接口；base_url填/v1根路径，不能填完整/chat/completions。保留已有backend="transformers"的进程内LLM，不自动下载模型。

### 本地BGE与API Embedding

```toml
[memory.embedding]
backend = "bge"
model = "model/bge-small-zh-v1.5"
device = "auto"
```

device可为auto/cpu/cuda，按现有BGE适配器编码。中文small v1.5为512维，已有英文small路径仍支持；不宣称适配任意Embedding架构。后端设备和Key不改变namespace，模型/tokenizer指纹改变才使用新空间。长文本与指令约束见[本地Embedding](本地Embedding配置.md)。

改用API时替换整个表，删除device：

```toml
[memory.embedding]
backend = "openai"
model = "你的Embedding模型ID"
base_url = "https://你的Embedding供应商/v1"
api_key = "${MEMORIA_EMBEDDING_API_KEY}"
```

也支持本地OpenAI兼容/embeddings服务；Key独立，不借用LLM凭据。验证float响应、索引/数量/维度、非零和有限数值。通用API不猜测其tokenizer。未来VL等角色应扩展ModelConfig槽位/消费者及测试，参数仍放models.toml；当前没有VL业务消费者，不能增加一个无效表冒充多模态能力。

## 4. 账号配置与密钥

全局槽位是默认；专属设置集中放同一models.toml的accounts.<服务器UUID>.llm.main/fast或memory.embedding。正式登录网关只选本人UUID，切换账号先清除前一个账号槽位；未配置者不会取得另一账号profile。credential_profile仍绑定UUID、模型及端点，从本人secrets加载DPAPI，不把明文Key合成全局值。

旧账号models.override.toml已迁入上述表，旧MCP JSON也已迁入mcp.toml。文件保存先校验全部槽位并原子替换，只修改目标账号表，保留系统/其他账号设置。研究模型激活仍需匹配已验证的source-grounded run；仅备份本人旧表到research/model-activations，激活回执也在research，不复制含其他账号信息的整份模型文件。改变模型/端点不会沿用旧profile或旧端点Key/thinking。正式PUT /api/settings/models仍403，本机管理员改文件后重启；MCP单独支持已有重载接口。

隐藏输入环境变量，在启动业务的同一终端执行：

```powershell
$taskModelKey = Read-Host 'LLM API Key' -AsSecureString
$env:MEMORIA_LLM_API_KEY = [System.Net.NetworkCredential]::new('', $taskModelKey).Password
Remove-Variable taskModelKey
.\scripts\cmd\start_backend.cmd
```

现有DPAPI profile无需重输；保留加密秘密和OAuth是凭据存储，不是额外配置目录。ACL工具默认保护data和config，仅当前Windows用户与SYSTEM；此为单机管理员边界，未宣称跨机器秘密分发或商业灾备完成。

## 6. 飞书和MCP实际位置

bot.toml的feishu/qq/telegram表统一管理三个通讯入口，应用凭据保存到data/secrets的DPAPI。命令configure_bot.py --channel选择平台私密配置，--disable只改开关、不删绑定。机器人收消息还需对应平台权限及网页登录后的独立绑定，不能用MCP OAuth替代。详见[统一接入](飞书QQ与Telegram通讯接入.md)。

mcp.toml的servers表集中定义search/github/feishu命令、cwd、env、工具名单、risk、timeout；accounts.<UUID>.mcp.enabled_servers明确开通账号。{project}、{account_dir}由服务器安全展开，新注册账号不会自动得到MCP或其他用户OAuth。configure_mcp只更新本文件；configure_feishu完成本人OAuth后修改本人启用列表。

实际程序：.mcp/node/node_modules/open-websearch、.mcp/node/node_modules/@larksuiteoapi/lark-mcp、.mcp/github/github-mcp-server.exe；scripts/mcp_server.py为stdio启动桥，随账号运行时启停，不另开网页服务端口。锁文件在deploy/mcp，安装清单.mcp/installation.json，真实检查在账号reports/mcp-check.json。旧根mcp_servers.example.json已删除，用config/mcp.example.toml替代。完整操作见[MCP部署](MCP部署与授权.md)。
