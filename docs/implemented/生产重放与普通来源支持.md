## 1. 生命周期水位与固定候选重放

[观测模块](../../memoria/observability/memory_trace.py)在账号SQLite安装事务内事件/epoch触发器，覆盖原话/撤销/公开导入、抽取任务、审核、普通记忆/操作/有效区间、来源依赖、向量/经历索引、Claim修订与View。事件仅记录阶段、表、实体ID、操作与观测时间，不复制原话；事务回滚一起回滚，无变化UPDATE不增加事件，重启不补造旧事件。水位从安装起算，不是全生命周期历史，既有LLM调用/usage仍由原trace账本记录。

统一访问返回production_trace：请求、账号、水位前后、候选/状态/要求/选择指纹及query-only覆盖特征；完整候选仍只在现有响应出现一次。Chat将轻量观测摘要加入本账号trace。changed_stages可见异步读取期间的变化，View自身物化也会记入，不能把它简单等同错误；输出仍以原来的来源/状态依赖复核为准。

[离线工具](../../memoria/experiments/production_replay.py)只读备份账号数据库为冻结输入，再在系统临时副本上执行同一访问代码；迁移/回填/视图写入不改冻结文件或生产库。默认lexical_only，显式--local-embeddings才使用账号配置的离线BGE；不允许远程Embedding、查询模型或Reader调用。副本水位和冻结来源均可核对；这不是重新运行旧抽取模型，未知的历史抽取输入/版本不能由元数据重建。

```powershell
# private-query.json为QueryRequest对象，只含问题和访问参数，不含gold或凭据
.\.venv\Scripts\python.exe scripts/research.py --user YOUR_USER capture-production --request .\data\private-query.json
# 可选离线BGE，不调用DeepSeek
.\.venv\Scripts\python.exe scripts/research.py --user YOUR_USER capture-production --request .\data\private-query.json --local-embeddings
# --input替换为上一步账号私有run下的production-capture.json
.\.venv\Scripts\python.exe scripts/research.py --user YOUR_USER replay-production --input CAPTURE_PATH --budgets 1000 2000 4000
```

replay-production校验账号与指纹，用同一捕获候选、query-only要求、Top-K和每档完整证据JSON预算比较四选择器，0模型调用。不能把字符/字节当远程Token；没有原可信tokenizer的reader_tokens重放拒绝。哈希检测意外改写，不是对抗本地篡改的签名；离线旧来源只用于诊断，不重新作为在线证据批准。

attribute是后验诊断接口：无标签返回unlabelled；只有显式提供必需来源ID时才区分来源不可用、状态未批准/不适用、未召回、候选未呈现、Reader未运行/契约失败/拒答与回答未评分。标签不进入检索或选择；ID覆盖不证明文本充分，真实语义正确性仍unknown。没有自动读取QA gold、生成评分或声称完整写入模型重放。

私密快照、候选原文和重放结果只在账号experiments目录；Git不收录。原trace已有脱敏不等于个人信息匿名化，本机管理员CLI和文件保留策略仍须按[账号边界](用户登录与数据隔离.md)与研究计划处理。商用长期留存/事件压缩尚未验收。

工程验收：新增11项重放/归因回归，与Claim、Reader、API及运行时共 **126项通过 / 49.64秒**。覆盖事务回滚、重启、冻结输入不变、跨账号/篡改拒绝、预算重放和在途水位变化；全部系统临时工程输入，0模型调用，不是研究质量成绩。

## 2. 普通记忆的版本化来源支持

[source_support.py](../../memoria/memory/source_support.py)保存普通记忆正文SHA及完整来源组，组内AND、组间OR。当前公开写入器以一条完整原话为组单位；精确去重/审核后的完整候选正文相同，才追加替代支持。纯模型相似强化只记操作，不成为新的完整支持；完整候选一致仍不等于原话语义蕴含已核验，不能标作semantic_support_verified。

来源组记录原话SHA、会话、记录时间和持久失效状态；删除、改写、换角色/会话/时间后整组失效，不能把文字改回就复活。来源撤回仍优先于历史读取。精确原文复制不增加独立lineage，每条记忆至多16组；这不证明不同措辞是独立见证。原来无来源的手工笔记保持原授权语义，不被一次确认改成仅依赖新来源的事实，也不伪造它的来源引用。

旧库只把原有依赖保守迁成一组；旧强化操作没有来源快照，不补造可替代证据。普通召回所有lane、历史、Reader发布前依赖及关联Claim父记忆共用可用性规则。统一来源补检选择仍有效的完整组，引用当前存活原话；正在生成的旧引用失效时关闭输出，不在生成中偷偷换引文。Claim编译器升为v6以隔离旧缓存。

撤回最初来源而仍有完整组时，保留当前记忆及既有有效区间；最后一组撤回时即使最初操作已在此前撤回，也能完成版本撤销及一次性恢复合法前版。事实级删除仍删除整条记忆，不靠另一组复活。原话/支持/强化操作/计数在同一事务写入，任一步失败全部回滚。没有自动合并旧重复事实或将公开语料转换成本人事实。

下一步：经历Dense/RRF仍按独立namespace和原话资格约束实现；受约束更新不允许仅凭相似Top-3覆盖其他主体/条件。来源语义充分性、真实保留率、独立支持及抽取F1仍未知。

第2节验收：两后端新增24项来源组反例，与普通一致性、来源事务、Claim组/父依赖、重放、Reader、API和长文等共 **205项通过 / 66.94秒**。全部系统临时工程输入，无真实模型调用或新语义评分。

## 3. 可选经历Dense/RRF与小规模真实检查

experience_mode支持bm25/dense/rrf，默认仍bm25。经历向量缓存按来源块、原话SHA、模型namespace和维度隔离；640字符块使用完整document分块编码，不截断剩余文本，过长块的粗向量为其token块聚合，不宣称细粒度互补性。Dense按符合身份/撤回/公开来源/recorded截止的向量精确扫描，0.45阈值为现有启发式，尚未校准；RRF只融合经历BM25和Dense两路，每路每块一次rank票，k=60。父来源多块仍按既有区间选择，不当作多个独立事实。

后台每批至多16块，取数/编码/提交分离，提交重验原话、会话、记录时间和模型空间。来源修改/删除先级联失效，失败批不部分发布。只接受进程内BGE或管理员配置的回环BGE服务；回环是部署信任假设，不能证明代理没有再转发。新增回环请求限制8秒、0重试，后台失败逐步退避至300秒；不让新维护无限拖住抽取队列。Dense不可用明确记录原因和已尝试调用，dense模式不冒充词面命中，rrf会披露缺失lane。

查询编码新增await后，在选择前再次核对来源/父版本与Claim状态；状态没有变化时保留首次读取路径，不把内部复核制造出的缓存命中写成首次收益。公开来源已在普通候选LIMIT之前排除，旧测试改为验证更早的排除位置。

私有冻结副本支持：

```powershell
.\.venv\Scripts\python.exe scripts/research.py --user YOUR_USER capture-production --request .\data\private-query.json --local-embeddings --index-local-chunks 16 --embedding-backend process
```

请求中设置experience_mode=rrf；index-local-chunks最多32，仅建副本，process仅对本地已有BGE目录作运行级覆盖，不改生产配置、不下载模型。固定池重放仍可比较四策略与多个预算，禁止把Embedding tokenizer代替Reader tokenizer。

2026-10-15真实本机检查：当前配置的回环8080服务连接失败，失败run保留；改用运行级进程内BGE后，账号冻结副本成功索引2个符合资格的原话块，实际维度512，完整性ok。以“项目记忆管理”查询0候选，保留未命中；另用已有原话作自检，BM25/Dense各命中1候选，RRF去重后呈现1个。后者是原话自检，不是独立QA或泛化质量。两次成功run及失败账本、原始查询/候选只留账号私有目录；0 DeepSeek调用、0生产写入、无全量LoCoMo、无新F1。

阶段边界：尚无ANN性能结论、跨消息邻轮/事件图、同预算真实QA提升；默认不切换RRF。维护等待/真实覆盖SLO仍待验证，调用数字区分外部批次、内部encoder批次与Reader请求。

第3节工程验收：新增12项经历向量回归，含经历/重放/Studio/Reader/API/运行时和普通支持共 **152项通过 / 51.75秒**。替身不作为真实质量，真实BGE检查另列；未运行全量LoCoMo。

## 4. 普通非精确关系的受约束更新

[ordinary_update_policy.py](../../memoria/memory/ordinary_update_policy.py)为普通写入增加保守veto：先判明同一显式self主体、有限槽位/唯一值、条件、模态和事实时间，再排相似Top-3。命名第三方/指代、复杂条件、相对事实时间、无明确生命周期的临时例外与不确定表达返回unknown，不交给相似关系模型当作可覆盖目标。现阶段只覆盖回答语言/详略、居住、有限饮食/爱好、预算及特定数字目标；不是自由属性或通用人物理解。

模型只能对合格目标提出关系；强化还要求值/极性一致，多值偏好通常并存。明确“改为/换成”且只有一个合格目标时，可提议替代；多目标时不靠模型自信消歧。单值变化须明确变化表达或人工/审核来源。原有明确目标correct/evolve接口和用户更正保护保持。更新提交事务内重验目标版本、来源和有效区间，模型等待期间变化则409，不覆盖后来版本。

不允许的关系保留为独立普通叙述，write_diagnostics列出原因、被过滤数和Top-3；这不是批准结构化Claim，也不证明原话语义充分。精确完整正文去重保持当前契约；若上游抽取已经丢失主体/条件，同文去重不能凭空恢复，仍需后续来源约束的Claim草稿/绑定。该阶段不宣称覆盖全部12槽位或自动修复历史语义。

第4节验收：新增16项更新闸门回归，与核心/更正、普通一致性、事务、审核、来源支持和既有审查共 **102项通过 / 24.64秒**。没有模型调用或新的语义评分。
