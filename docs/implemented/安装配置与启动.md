前端源码统一位于[frontend](../../frontend/README.md)：`chat/`独立聊天、`studio/`管理后台、`shared/`共用登录/API。一套依赖和构建，旧/app/工作台已移除；聊天页只列个人原生对话，公开导入资料在Studio查看。

以下为 **Windows PowerShell**，除注明外从仓库根执行，无需激活.venv。本机路径为`C:\Users\zero\Desktop\Memory-Project\Memoria`，新机器先获取仓库：

```powershell
# 已有项目不重复clone
git clone https://github.com/ZJ331456/Memoria.git
Set-Location Memoria
# 本机可直接 Set-Location 'C:\Users\zero\Desktop\Memory-Project\Memoria'

if (-not (Test-Path .venv\Scripts\python.exe)) { python -m venv .venv }
# CUDA机器先按下节选择官方PyTorch wheel，再安装全部分类依赖。

# 保留已有私密配置

.\.venv\Scripts\python.exe -c "import sys; print(sys.executable); print('isolated:', sys.prefix != sys.base_prefix)"
```

本机已验证Python3.13.5、Node22.16.0、npm10.9.2。Python依赖统一在根requirements.txt；Node依赖仍分别由frontend锁文件和.mcp工具维护。这是当前平台证据，不代表全部系统已验收；不向conda base或全局npm安装项目包。

## 依赖清单与平台脚本

[requirements.txt](../../requirements.txt)是唯一Python安装清单，原有版本约束保持，pytest补入工程测试分类。分为HTTP服务/配置、本地Qwen/BGE与下载、SQLite向量扩展、飞书SDK、研究评分、图表、测试七类。`pip install -r requirements.txt`安装全部类别；注释不是pip的可选分组，不会自动按类别筛选。本地模型和飞书等功能仍按配置启用，安装库不会自动配置账号、下载权重或调用模型。

PyTorch保留`torch==2.9.0`，接受当前`2.9.0+cu126`构建；CUDA机器应在安装完整清单前，按实际硬件选择官方wheel。本机RTX4060使用：

```powershell
.\.venv\Scripts\python.exe -m pip install torch==2.9.0 --index-url https://download.pytorch.org/whl/cu126
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

已有匹配的CUDA环境不强制重装。清单不绑定全局PyTorch索引，其他Python包使用正常包索引；CPU/CUDA选择与驱动兼容性参照[本地Embedding说明](本地Embedding配置.md)。

```text
requirements.txt        # 唯一Python依赖清单
scripts/
├─ cmd/                 # Windows入口，可双击或从任意目录调用
│  ├─ build_frontend.cmd
│  ├─ start_backend.cmd
│  └─ stop_backend.cmd
├─ sh/                  # Linux预留，目前只有说明，没有已实现的.sh入口
├─ backend.ps1          # Windows后台生命周期实现
└─ frontend.ps1         # Windows前端构建实现
```

[CMD说明](../../scripts/cmd/README.md)与[Linux预留说明](../../scripts/sh/README.md)由scripts统一导航。根目录不保留重复CMD或旧requirements兼容文件。Python研究和绘图工具仍放scripts，未来Linux脚本须另行验证进程归属、配置/账号隔离和停止行为。

## 模型方案：选择一种

准备`model/bge-small-zh-v1.5/`，使用本地LLM时另备`model/Qwen3.5-2B/`。模型被Git忽略，clone不会包含权重；本项目没有通用Qwen下载CLI，需有效的本地Safetensors/tokenizer/config。

```powershell
# 完成上节依赖安装后，准备本地BGE权重；已有权重无需重复下载。
.\.venv\Scripts\python.exe scripts/download_embedding.py
```

已有环境/模型时跳过；BGE下载固定revision并核对SHA/大小。驱动与wheel按[Embedding说明](本地Embedding配置.md)和[PyTorch官方安装表](https://pytorch.org/get-started/previous-versions/)核对。

### A. 远程LLM + 进程内本地BGE

先复制`configs/models.example.toml`到忽略的`configs/local/models.toml`，在根config.toml设置`[models] file="configs/local/models.toml"`。下面的模型表写到独立models.toml；完整目录、API Embedding及覆盖优先级见[配置说明](配置目录与模型后端.md)。模型名称使用实际账号可调用ID。

```toml
[llm.main]
backend = "openai"
model = "deepseek-flash"
base_url = "https://api.deepseek.com/v1"
api_key = "${DEEPSEEK_API_KEY}"
[llm.fast]
backend = "openai"
model = "deepseek-flash"
base_url = "https://api.deepseek.com/v1"
api_key = "${DEEPSEEK_API_KEY}"
[memory.embedding]
backend = "bge"
model = "model/bge-small-zh-v1.5"
device = "auto"
```

新机器用环境变量时，在**启动业务服务的同一终端**隐藏输入，不打印Key：

```powershell
$taskSecureKey = Read-Host 'DeepSeek API Key' -AsSecureString
$env:DEEPSEEK_API_KEY = [System.Net.NetworkCredential]::new('', $taskSecureKey).Password
Remove-Variable taskSecureKey
```

本机qin已有账号绑定DPAPI profile，无需重输或覆盖。`data/users/<UUID>/config/models.override.toml`会覆盖槽位，已有覆盖时只编辑服务器models.toml可能不改变实际配置。`configure_research_model.py`仅保存研究profile，单独执行不激活生产；见[脚本说明](../../scripts/README.md#研究与模型配置)与[统一接口](本地与远程OpenAI统一接口.md)。

### B. 本地Qwen/BGE共用HTTP模型服务

在独立models.toml把main/fast设为backend="openai"及8080的/v1根地址；Embedding可继续进程内BGE，也可按[配置说明](配置目录与模型后端.md)设为HTTP。**终端一**启动8080：

```powershell
.\.venv\Scripts\python.exe scripts/serve_local_llm.py --model model/Qwen3.5-2B --embedding-model model/bge-small-zh-v1.5 --device cuda --host 127.0.0.1 --port 8080 --max-context-tokens 8192 --warmup
# 另一个终端只读确认
Invoke-RestMethod http://127.0.0.1:8080/health
Invoke-RestMethod http://127.0.0.1:8080/v1/models
```

设备可选cpu/auto；本机验证为CUDA。服务提供chat/completions与embeddings，Qwen总输入+输出默认8192 token、BGE单块512 token；health存活不是模型质量证明。warmup加载并运行本地LLM，长文分块由记忆链路执行，直接超长embedding不会静默截断。[完整接口边界](本地与远程OpenAI统一接口.md)。

## 构建与启动2237业务

已有`.venv`、私密配置和Chat/Studio构建时，双击scripts/cmd目录的[start_backend.cmd](../../scripts/cmd/start_backend.cmd)，或从仓库根执行：

```powershell
.\scripts\cmd\start_backend.cmd
.\scripts\cmd\stop_backend.cmd
# 查看 / 停止同一脚本管理的进程
.\scripts\cmd\start_backend.cmd -Action Status
.\scripts\cmd\start_backend.cmd -Action Stop
```

后台隐藏运行，根地址http://127.0.0.1:2237/进入Chat，http://127.0.0.1:2237/studio/进入后台；日志在`data/logs/system/`。双击[stop_backend.cmd](../../scripts/cmd/stop_backend.cmd)关闭业务及其MCP子进程；端口已有其他服务时会提示占用，不重复启动或误杀。脚本启动业务服务并托管已构建的两套界面；方案B的8080模型服务仍需先准备，首次构建步骤见下文。[配置、端口与停止说明](本机后台启动与停止.md)。

先构建，再在**终端二**启动；方案A无需另起8080。

```powershell
Push-Location frontend
npm ci --cache .npm-cache
npm run build
Pop-Location
.\.venv\Scripts\python.exe main.py --config config.toml --host 127.0.0.1 --port 2237
```

| 地址 | 用途 |
| --- | --- |
| http://127.0.0.1:2237/ | 独立Chat：个人聊天、新对话、流式回复与停止生成 |
| http://127.0.0.1:2237/studio/ | 管理后台：数据总览、历史搜索、记忆/候选与来源核对 |
| http://127.0.0.1:2237/docs | Swagger接口契约 |
| http://127.0.0.1:2237/api/health | 业务进程存活，匿名可读 |
| http://127.0.0.1:8080/v1/models | 方案B独立模型服务 |

```powershell
Invoke-RestMethod http://127.0.0.1:2237/api/health
```

Chat/Studio503时先构建再重启；可双击[build_frontend.cmd](../../scripts/cmd/build_frontend.cmd)一次构建两端，源码分工见[frontend](../../frontend/README.md)。端口占用先核对已有服务，不重复起两份。修改模型override后重启业务。当前按单个业务进程运行，多worker租户生命周期、任务和MCP协调尚未验收。

### 首次账号与登录

独立Chat与Studio共用登录/注册入口，切换账号会清空旧资料，分别读取各自数据；新机器也可在本机隐藏输入建立自己的账号：

```powershell
.\.venv\Scripts\python.exe scripts/manage_users.py reserve your_username
.\.venv\Scripts\python.exe scripts/manage_users.py set-password your_username
```

用户名3–32位小写英文/数字/下划线，以字母开头，密码12–128字符；也可通过/api/auth/register注册。本机qin已配置，正常登录即可，重设会撤销会话。正式业务始终要求Cookie/Bearer登录，api_token空不免登录。Studio不保存明文密码或Bearer，见[用户隔离](用户登录与数据隔离.md)。

### 前端开发模式

API保持运行，在第三个终端：

```powershell
Push-Location frontend
npm ci --cache .npm-cache
npm run dev
```

Chat访问http://127.0.0.1:5173/，Studio访问http://127.0.0.1:5173/studio/，/api代理到2237；部署模式只需构建产物和2237，不需要Vite开发进程。

## 可选MCP与公开诊断来源

手机飞书机器人对话使用独立的[消息入口与绑定流程](飞书机器人对话接入.md)：安装requirements.txt、运行私密配置命令、发布平台事件/权限后，登录Chat点击“连接飞书”。MCP文档授权不会自动接收机器人消息；应用ID、Secret及绑定只保存本机忽略目录。

这些不是最小启动必需项，仅配置已有账号：

```powershell
.\.venv\Scripts\python.exe scripts/install_mcp.py
.\.venv\Scripts\python.exe scripts/configure_mcp.py --user your_username
.\.venv\Scripts\python.exe scripts/check_mcp.py --user your_username
# 飞书首次私密输入并授权；重授权可加 --login-only
.\.venv\Scripts\python.exe scripts/configure_feishu.py --user your_username
```

依赖在.mcp，凭据按账号隔离；飞书回调http://localhost:3000/callback。安装、握手、授权、业务调用分别核验，详情见[MCP文档](MCP部署与授权.md)。

```powershell
# 可选公开来源；已有qin语料无需重导
.\.venv\Scripts\python.exe scripts/prepare_real_dialogues.py --limit 50 --user your_username
```

50段/206原话来自LCCC，进入账号实验空间；身份/事件时间未知，不生成本人Claim。旧个人历史仍不导入，来源/许可见[来源清单](../../assets/data-sources/README.md)。
