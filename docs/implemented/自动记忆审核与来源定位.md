# 记忆审核、自动入库与来源定位

更新：2026-10-16。[当前完整机制](LLM自动审核与人工辅助.md) · [API](API接口文档.md) · [账号隔离](用户登录与数据隔离.md)

默认由模型主审，人工辅助。原生聊天结束后worker抽取最多3候选，另一次LLM审核原话支持与长期价值；低风险Supported自动保存，复杂条件、敏感/凭据、计划/他人、来源失效及单值冲突分别拒绝或保留辅助。manual配置可保留全人工流程。公开实验资料绝不直接成为本人事实。

Studio历史中“LLM提取并处理”只请求当前这一条本人原话；旧空任务可重处理但留回执，已有候选不重复生成。手动提出仍可用，之后按当前策略处理。候选页默认全部记录，同时展示LLM已入库、需人工辅助和已拒绝；自动入库不是无记录绕过审核。

memory_reviews状态仍为pending→applying→approved/rejected；失败恢复pending。memory_review_assessments追加模型/规则决定、输入指纹、原因和已知usage；未配置/失败不伪造成模型成功，相同输入后台不反复付费。发布事务内复核来源并同时写记忆、简单Claim和审核回执；网络/Embedding调用在事务外。

人工结构化联动的value_not_literal不再一律拒绝：仅纯改写/别名可以再经LLM Supported判断；主体/条件/时间/冲突等硬限制仍须解决。不能确认结构化字段时可取消联动，只明确保存普通记忆。模型不是现实事实验证器，不能据此宣称长期效果或F1。

原文始终由账号UUID保护；读取删除来源返回不可用。只有当前有效状态参与正常访问；纠正保留旧版本，撤销继续检查完整支持和父依赖。队列最多500条、尚无游标，扩容与治理专用视图仍待计划验收。
