# 记忆候选审核与来源定位

[文档导航](../README.md) · [个人记忆模块](../../memoria/memory/README.md) · [API](API接口文档.md)

更新：2026-10-15。正式账号UUID隔离，Chat负责对话，Studio负责原话、候选、长期记忆与高级治理；以SQLite为权威，不使用Markdown文件当队列。

## 从对话到记忆

保存原话不等于产生长期事实。原生聊天结束后后台任务提取候选，只有值得保存且合规的结果才入队；普通提问、临时消息和凭据不能强行形成长期事实。公开导入对话属于账号实验资料，不自动产生本人候选。已有任务completed只表示完成处理，候选仍需批准。

在Studio“历史对话”阅读有效本人原话，点击“提出记忆候选”，填写原话支持的事实/偏好并确认含义；该动作不调用LLM，只创建pending。然后去“候选审核”并排核对原文，可编辑、明确批准或拒绝；批准可能调用Embedding。普通批准不自动成为结构化Claim，联合批准另需明确勾选及完整字段。

“记忆处理与服务”解释历史、提取、审核、入库的各阶段，显示最近50个任务。新任务在同一租约事务保存extracted_count/staged_count；0表示明确无候选，NULL表示旧任务未记录。不能根据旧completed和空审核队列断言模型返回了空数组。失败任务可在确认费用后单条重试；不会自动重放全部历史。

## 状态、来源和事务

- `memory_reviews`按(job_id,ordinal)幂等保存，pending→applying→approved，或pending→rejected；失败/重启的applying恢复pending。手动候选用manual:来源消息ID标记，不伪造抽取任务；相同来源、正文和类型的待审项复用。
- 提出及批准均检查当前账号来源、用户角色、公开导入归属、撤销和原文一致性；来源失效不能批准。仅有SHA/span一致性不等于自动语义证明，含义仍需核对。
- 普通批准复用MemoryEngine的来源、去重、强化/替代及操作账本；可选择与Claim同一事务发布。只有有效active记忆参与正常访问和Markdown投影，拒绝项不入库。
- 来源/会话删除后回查404，不伪造缺失原文；有效性、完整支持组和父依赖沿用[来源支持机制](生产重放与普通来源支持.md)。
- 长期记忆可纠正并保留版本及旧来源，支持导出可读Markdown；这不是完整账号备份或注销。

## 接口与边界

GET /api/memory-reviews默认100、最大500条，支持pending/approved/rejected/all；尚无跨页游标。POST /api/memory-reviews/propose只提出待审候选；approve/reject明确决定。重复决定409，字段非法422，无效来源拒绝；GET /api/studio/pipeline只读状态、不调用模型。来源可用claim-source或messages/source读取，Studio支持消息锚点和高亮。

个人显式新增和memorize工具保留原有写入政策；此页不会批量自动批准。共享Agent另用proposals/ACL与X-Agent-Key，仍先过登录网关，见[共享治理](记忆治理与多Agent共享记忆.md)。未知人物、事件日期和长期效果保持未知。
