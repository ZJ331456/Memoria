## 单次请求与长期记忆

旧worker对有效本人消息调用LLM提取最多3条持久事实，再独立审核。代码没有以“我想/喜欢”为必要条件的词表开关，但提示偏向事实、偏好和目标，缺少单次行为的积累过程。一次推荐请求返回0事实可以合理；长期重复行为也永远不进入形成过程，则是机制缺口。

用户指定的生产消息只读核查为completed、1次尝试、0候选，不是未入队或审核关闭。原文、ID和私有回执不公开。新链路为：

```text
本人原话 Evidence
  → Observation：本次确实说过/做过什么，绑定原话版本和span/SHA
     ├─ 明确、持久自述 → 原有LLM主审/风险门控 → 普通记忆/可选Claim
     └─ 单次行为/关注 → 保存观察，等待后续证据
  → 同主题、同条件、同极性，满足跨会话门槛
  → LLM提出Pattern及必要观察ID
  → 第二次模型核验完整来源组 + 服务器来源/风险/版本检查
  → 原有长期记忆存储 → 强化、版本更新、降级和失效
```

Observation不是批准事实；Pattern是有边界的近期推断，不能冒充永久偏好、人格或疾病。记录时间不是事件发生时间，不补造事实日期。

## 实现与存储

[formation.py](../../memoria/memory/formation.py)使用现有fast优先模型，严格JSON最多4条观察，类别包含fact/preference/habit/behavior/goal/workflow/experience/interest。不要求偏好关键词；一次搜索可以观察为“本次查找某主题”，不能直接推断稳定爱好。助手回复、第三方、公开导入、假设和凭据不作为本人形成证据。

[formation_store.py](../../memoria/memory/formation_store.py)在原账号SQLite新增：

| 表 | 保存内容 |
| --- | --- |
| memory_formation_runs | 抽取策略、原话SHA、模型与usage，同任务/原话版本/策略可复用 |
| memory_observations | 原话ID、会话、记录时间、SHA、quote/span、类别/主题/条件/极性和自述/持久性标记 |
| memory_pattern_versions | 模式、操作、前序版本、输入指纹、审核/记忆关联、时效和成本 |
| memory_formation_candidates | 原审核候选与完整观察组绑定 |
| memory_formation_events/calls | 操作及模型阶段、耗时、已知usage和失败；未知usage为null |

观察与直接候选在原stage_memory_reviews事务中保存。租约、原话或证据不匹配时整笔回滚；改写来源持久失效观察，删除来源级联移除观察。把原话改回不自动恢复失效项；升级不补造旧观察，不批量重提取历史。

普通失败重试复用已落盘的观察；用户明确再次发起历史提取则保存新的请求代次，不能把旧缓存伪装成新模型提取。跨会话计数仍按原话版本去重，反复点击不增加独立证据。巩固异常单列事件和成本，观察提取完成不被改成“提取失败”；Studio显示异常记录，后续新证据可再次触发，当前不后台无限重试。

## 巩固与演化边界

默认至少3条不同原话、2个会话；同文复制只计一次。主题/条件/极性分组，最多24观察；每条新任务最多1次模式整理和1次模式审核。门槛是工程起点，不是已校准的习惯判据或独立见证概率。每条直接持久候选仍各需一次审核。

模型只能引用给出的观察ID，审核须引用完整组所有来源；提交时再次校验来源版本。模式禁止自动创建Claim。完整支持采用原有组内AND、组间OR，不能把一条原话的支持伪装成整个推断的充分证据。

| 操作 | 当前行为 |
| --- | --- |
| ADD | 足够证据和审核通过后创建近期模式 |
| REINFORCE | 相同结论精确去重，追加完整支持组，不新增同文事实 |
| UPDATE | 只更新同主题/条件/极性的一条有效自动模式，复用Store不可变替代与区间 |
| MERGE | 同组模式与新证据整理为一个结论，不任意跨事实/跨条件合并 |
| DELETE | 只记录需辅助处理的建议，不删除原话、人工事实或Claim |
| NOOP | 保存无新结论的决定与成本，不强造长期记忆 |
| RETIRE | 来源失效或到期退出使用，保留历史和审计，不称为隐私物理删除 |

自动模式不能接管人工笔记或用户纠正；目标在模型等待期间改变则停止提交。发表、完整支持、审核和演化状态原子完成。来源撤回后，只有另一完整组仍有效才可继续使用。自由属性自动演化、跨极性自动裁决、任意多事实合并和模型物理删除尚未交付。

当前模式必须由自己绑定的完整来源组支持，不能借旧模式的证据给新模式“续命”；待审旧提案也不能覆盖后来的有效head。严格来源Reader不将多来源推断拆成一个单例事实，模式通过有边界的普通记忆/Core使用；这不等于已完成任意多来源推断的结构化Claim问答。

## 核心、配置与界面

近期有效、无条件的审核模式可进入有限Core，明确标为推断；严格Claim查询不夹带Core。其余走原有按需检索。Core仍受PromptAssembler总预算和发布前依赖复核约束，近期性下降后退出核心；默认90天后退出当前使用，历史保留。时间权重和阈值未校准，不声称遗忘策略最优。

近期性依据最新必要原话的记录时间，而不是重新整理的模型时间；未被模式选用的新观察不能延长该模式的有效期。Core采用半衰期权重至少0.5的等价时间门槛。默认45天后不再进入核心，观察90天后软归档；普通显式事实不因此被改写为相反状态。

原config/system.toml统一管理，不新增配置文件或模型供应商，模板见[system.example.toml](../../config/system.example.toml)：

```toml
[memory.formation]
enabled = true
min_sources = 3
min_sessions = 2
max_observations = 24
retention_days = 90
core_half_life_days = 45
core_chars = 1200
```

enabled=false恢复原直接候选提取，不删除观察或绕过模式失效；approval_mode=manual不自动整理/发布模式。Studio“记忆处理与服务”展示观察、形成路径、模式/版本及来源回查；Chat和历史区分等待积累与0候选/失败/入库。刷新只读，不调用模型。

GET /api/memory-formation、/api/memory-observations、/api/memory-patterns均走现有登录网关，只读当前账号数据。直接读取SQLite仍是本机管理员权限，不是HTTP租户隔离。
