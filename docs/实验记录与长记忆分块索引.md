## 生产长记忆

本地 BGE 的写入、更正和回填现在通过 `EmbeddingClient.embed_documents` 按实际 tokenizer 分块。每块最多 512 token，含 special token；连续原文字符 span 覆盖全文，不通过 decode 改写文本。HTTP BGE 客户端也需要项目中的 `model/bge-small-zh-v1.5` tokenizer，服务必须使用相同权重/编码策略。通用远程 Embedding 保持原有文档接口，本轮未定义任意供应商的分块协议。

父记忆保留完整正文和版本；`memory_embedding_chunks` 保存独立向量、模型 namespace、块序号、原文位置、token 数和原文 SHA。归一化块向量均值只是父记忆粗向量，检索按**最大块余弦相似度**给父记忆打分，再参与原有 RRF。多块不会产生多个事实版本，也不会重复占满返回名额。SQLite KNN 会扩大候选，直到找到足够的不同父记忆；JSON 回退沿用受限父候选扫描。

父版本、区间、父向量、全部块在同一 SQLite 事务中持久化。更正关闭旧版本和其当前块索引；撤销恢复旧版本时重新加入其块；删除级联删除块记录。历史查询按父版本有效区间过滤，保留历史块以支持时间旅行。延迟回填先检查父版本仍活动且正文未变化，避免并发更正/删除后写回旧索引。

返回的 `content` 仍是完整正文；`retrieval.chunk` 给出命中位置，多块记忆另有 `retrieval_excerpt`。PromptAssembler 与 recall 工具优先使用该片段，并标注父 ID 和原文位置。最终上下文仍受字符预算约束，不能把完整索引覆盖解释成最终 prompt 全文可见。

旧记忆即使已有一条向量，只要没有当前空间的完整块索引，也会被识别为待回填。查询按既有批量上限补齐候选，显式重索引可提前处理旧数据：

```powershell
# 先重启本地模型与 Memoria 服务加载新代码，再运行；服务 Token 按原 API 认证方式传入。
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:2237/api/memories/reindex?limit=1000'
```

这不是全库后台迁移：当前一次最多读取指定数量的活动父记忆，读路径仍有回填成本。后台游标、蓝绿切换及大库覆盖审计仍是 P1。新写入和已回填的长文不再因整条输入超过 BGE 上限而丢失 Dense 编码；服务不可用、tokenizer 缺失、查询超限等真实错误仍沿用降级机制。

## 实验记录

新的中文 runner 为每次 run 建立独立目录，默认位于 Git 忽略的 `data/experiments/companion/`：

| 文件 | 内容 |
| --- | --- |
| `manifest.json` | commit、dirty diff SHA/未跟踪文件 SHA、数据 SHA、模型权重/配置/tokenizer SHA、revision 可用值、环境、硬件、角色参数、预算、启动/结束时间、产物 SHA |
| `events.jsonl` | 每次输入后的抽取候选、批准写入动作、当前活动记忆/来源、块数和写入阶段耗时 |
| `cases.jsonl` | 每个检查点的查询、召回来源/片段/排名、实际回答、prompt 字符数、阶段耗时和错误 |
| `prompts.jsonl` | 每次实际 LLM 调用的消息与 prompt SHA，便于重放抽取/决策/回答 |
| `calls.jsonl` | 角色、实际参数、原始返回、finish、usage、重试、错误、总耗时及流式首段可见文本时间 |
| `metrics.json` | 所有请求题目的分母、错误、来源/关键词诊断、分角色 token、失败调用及缺少 usage 的数量 |

中断时未尝试的题目也写入失败行；不能只对成功响应计算分母。manifest 的 `completed` 表示运行记录完成，不表示质量检查全通过。`length` 或空最终正文会作为失败保存；合法抽取 `[]` 是模型行为，质量失败由后续来源/回答诊断体现。

模型 revision 未公开/未记录时保留未知值，以实际本地文件 SHA 定位，不臆造版本。HTTP 模型目录属于客户端声明；一键检查另记录由自己启动的服务入口 SHA、设备、模型目录、总上下文及关闭思考策略。seed 只作为协议标识归档，当前输入顺序固定、贪心生成；UUID 随机导致 prompt token 数可能略变，不承诺 GPU 逐位一致。默认只允许本地模型，远程调用须显式 `--allow-remote` 并填写真实的供应商思考策略。

目前标准记录已用于**中文内部诊断**；既有公开 benchmark 的历史报告保留原协议，其 runner 的完整 manifest 迁移仍待后续。原始模型、私人配置、数据库和日志不提交 Git，仅核验汇总与手写小夹具入库。

## 阶段计时

产品 trace 的 `metadata.stage_timings` 记录压缩、query planner、检索、候选/回填、query embedding、块候选、融合、prompt 组装/预算、reader 与工具执行等实际执行阶段。实验写入另记录 chunking/document embedding，LLM 分 reader/extractor/decider/judge。未执行角色不会伪造耗时或 token；视图机制尚未实现，没有 view-check 指标。

耗时是包含等待、客户端/HTTP、调度和推理的墙钟时间。嵌套阶段重叠，**不能相加**；也不能称为纯 GPU kernel 时间。失败/取消阶段计入 failed 次数。TTFT 取首段非空可见流式文本，排除 reasoning/tool delta，普通非流式调用为 null；工具模式可能缓冲生成，因此该指标不是底层第一个采样 token 的时间。

第二次真实运行，人工整理条件每题检索以下阶段；单位 ms，8 个 probe，BGE/LLM 已被长文 smoke 预热，单并发小库：

| 父/块向量候选总阶段 | 14.599 | 24.273 |

## 中文变化轨迹与真实结果

4 个虚构轨迹、8 个检查点：居住地明确更改、平常偏好与一天例外、本人/朋友归属、计划取消但尚未发生。system 输入与 gold 文件分开；自动抽取模式不读取人工整理内容，scorer 只在全部模型调用结束后加载 gold；检查点问答不进入未来输入历史。来源日期写在原消息中，Store 区间仍是摄入时间，尚未建模真实世界事件时间。

| 条件（两次独立运行均同计数） | 运行错误 | 来源检查 | 回答关键词检查 | LLM 调用 |
| --- | ---: | ---: | ---: | ---: |
| 人工整理写入 + BGE + Qwen reader | 0/8 | 8/8 | 7/8 | reader 8；其他角色 0 |
| 生产抽取 + 自动批准候选 + BGE + Qwen reader | 0/8 | 0/8 | 0/8 | extractor 8、reader 8；decider/judge 0 |

这不是语义 QA 正确率，报告的 `semantic_qa_accuracy=null`；尚无独立人工核验或 20 用户/240-query 研究数据。人工整理模式由夹具明确写入/纠正事实，不代表模型自主学习。自动抽取复跑的 8 次原始响应全为 `[]`，没有任何活动记忆；本条件给抽取 worker 的助手文本为空，不能据此断言所有真实聊天都会抽取失败。它指出当前协议需要先做独立开发样例的角色/消息格式排查，而不能直接进入状态算法效果比较。

人工整理 `p-before` 题已召回“计划去南京、尚未去过”，reader 仍回答“不知道”。这是实际失败，不是关键词评分的假阴性。两次运行的全部失败保留，未依据这 8 题调整阈值、前缀或 prompt。

长文真实 smoke 覆盖 **3626 字符、7 块、最长 512 token、原文覆盖 100%**，原生 SQLite 块索引启用；尾部“鸡肉过敏”进入 900 字符帧，更正“牛肉”后旧版本被排除。两个查询最大块相似度约 **0.3560 / 0.3293**，低于原有 0.45 floor，因此向量通道排名为 null，父记忆通过关键词/BM25 通道返回，但仍使用向量最佳块作为片段。**解决编码超限，不等于每个语义问句都达到召回门槛。** 首次脚本因把语义排名当硬断言而中止的报告也保留；第二问是随后用于排查的探针，不是独立测试集成绩。

第二次共 24 次 LLM 调用，reader/extractor 原始 usage 均齐全：人工整理 reader 总计 1733 token；自动抽取 reader 672、extractor 908，总计 1580。没有调用外部 API、个人数据库或生产审核队列。临时服务结束后释放自己的进程。

## 复现与下一步

```powershell
# 无模型：隔离库核验人工写入与来源生命周期。
.\.venv\Scripts\python.exe -m tests.regression.run_companion --vector-backend json
# 真实本地 GPU：临时隐藏服务，长文检查 + 两种中文条件；模型必须已经在项目目录。
.\.venv\Scripts\python.exe scripts/check_companion_local.py --device cuda
# 已有模型服务时直接运行；--config 指向带独立 storage 路径的实验配置，避免继承个人模型 override。
.\.venv\Scripts\python.exe -m tests.regression.run_companion --config experiment.toml --mode extracted --embedding --reader
```
